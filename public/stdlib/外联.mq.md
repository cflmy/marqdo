`lib/外联` 用本机解释器运行代码围栏和内联源码。v2 不改 Markdown 表面，新增结构化记录、JSON 进出、并行扇出、Python/Node 持久内核和显式状态桥。

文件仍然是一篇文档：绑定的代码围栏是可读的 Markdown，`外联.*` 把它变成可执行单元。

`金额格式` =
```node

process.stdin.on("data", chunk => { input += chunk; });
process.stdin.on("end", () => {
  console.log(JSON.stringify(new Intl.NumberFormat("zh-CN", {style:"currency", currency:"CNY"}).format(JSON.parse(input))));
});
```

我们先**单个 = [计算并保存 单个](外联.调用(代码=`金额格式`, 输入=21))**，供下一步使用。

随后我们**[显示当前步骤的结果](> 打印 内容=`单个`)**。

输入编码成 JSON 写到 stdin；stdout 的最后一个值再解析成 JSON。想同时保留原始记录时，用 `执行` 的 `输出="json"`。

view 中的单元。

`foreign.session` 拥有文档的内核状态。内核和单元顺序都是作为参数传入的普通表格，名字可以自由选择：

```text
`分析内核` =

| 名称 | 语言 | 命令 | 说明 |
|------|------|------|------|
| 分析 | node | | 共享分析 |
| 复核 | node | | 独立复核 |

`分析单元` =

| 单元 | 内核 | 说明 |
|------|------|------|
| 准备数据 | 分析 | 写入状态 |
| 计算指标 | 分析 | 读取状态 |
| 独立复核 | 复核 | 隔离内核 |

`会话` = > foreign.session kernels=`分析内核` cells=`分析单元`
```

`view` 消费 `会话` 句柄，提供 Run All、Step、切换内核、journal 和单元状态。没有 `会话` 时，view 的 cells 是无状态的一次性运行：同一套外壳，但没有持久内核。没有第二个 CLI 模式。原生分析与 Intl 示例见 [`features/19-外联视图单元.mq.md`](../features/19-外联视图单元.mq.md)。

安全默认值。

| 边界 | 默认 |
|---|---|
| 执行 | 需要宿主执行能力 |
| Shell | 不经过 shell；参数显式切分 |
| 输出 | 有界，带 truncated |
| 超时 | Unix 杀进程组 / Windows taskkill /T |
| 工作目录 | 文件沙箱根目录；不隐式越界 |
| 并行 | 扇出有上限；每个任务隔离 |
