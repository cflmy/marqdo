先用固有能力，外联只补真实的能力缺口。本页复用 [原生报告例程](../../examples/foreign-native-report/index.mq.md)，让统计在 Marqdo 中完成，再通过已支持的 Node 持久内核使用 Intl。阅读例程的源码即可找到可以独立调用的参数、返回值与失败约束。

在仓库根目录调用 marqdo call public/features/19-外联视图单元.mq.md main --effects process.exec --fs-root . --json 可以获得真实报告与视图计划。使用 view 导出同一份源码即可运行下面声明的单元。这里采用函数标题 main，便于作为工具直接调用；不需要 Python 解释器或另一套笔记本入口。

## main

| 返回 | 类型 | 说明 |
|---|---|---|
| result | map | 包含 report、formatting 及内核/单元/初始值的视图计划；失败时返回实际 Result |

格式化结果中的数字会显示为 950.00 与 158.33，货币标志由区域设置决定；原生 report 保留未格式化的数值。

本页的六笔订单全部由 Marqdo 固有能力处理，得到合计 950、数量六、四个区域的订单数、合计、均值和总体标准化跨度。分组、排序、统计与数值运算都不需要外部脚本；真正交给 Node 的只有 Intl 本地化货币格式。直接调用本页 main 需要 process.exec，Node 应预先安装。成功返回的计划包含 report 原始报告和 formatting 展示结果，调用者可以继续验证具体数值。

共享例程有独立的参数及返回表，区域键和金额键都由调用者明确指定，因此中文字段不需要重命名成另一套 JSON 拼接语言。本页和英文页共同调用一份原生算法，避免两个版本逐渐出现不同的统计规则。纯数据分析可以直接调用例程的 analyze_orders，不需要任何进程授权；空输入、单元素区域与相同金额的区域也有清楚的定义。金额只是示例数值，展示的两位小数由 Intl 决定，不宣称是金融十进制定点模型。

视图的分析内核先输出已经算好的报告，并创建本地化格式器；同一内核中的第二个单元继续使用这个格式器。因此 Run All 的顺序是明确的执行依赖，直接先运行格式化单元应展示真实的未初始化状态。复核单元使用另一份内核和自己的格式器，体现状态隔离。两个内核收到的是报告的数据拷贝，谁都不会重新实现一份分组算法，也不会修改 Marqdo 的源订单。

用于验证工具返回值的低层格式化例程单独创建并关闭了一个持久内核：第一次求值创建格式器，第二次复用状态。它检查每次求值的 ok，遇到可恢复错误时关闭仍存活的内核，再返回真实诊断。用于视图的会话随后才被声明；工具验证的内核不能暗中给视图提供状态。视图的静态导出与交互模式运行同一批单元，输出来自实际执行，不用预写的通过文字冒充结果。

正文先交代数据来源和边界，再把调用放入相应的句子。下面的订单、内核、单元和初始值都是普通表格；三段绑定的 node 围栏才是明确外联的代码。整个操作不要求向终端输入 JSON，也不生成文件读取器。若解释器不可用或格式化失败，会在创建可用视图之前把失败交给调用者。

接着**会话 = [用普通表格声明显式的视图会话](外联.会话(内核表=`内核`, 单元表=`单元`, 值表=`初始值`))**，让两份内核获得同一个原生报告的独立 JSON 拷贝。

`计算` =
```node
var money = new Intl.NumberFormat("zh-CN", {style:"currency", currency:"CNY"});
console.log(JSON.stringify(report));
```

`格式化` =
```node
console.log(money.format(report.total));
console.log(money.format(report.average));
```

`复核` =
```node
var reviewMoney = new Intl.NumberFormat("zh-CN", {style:"currency", currency:"CNY"});
console.log(JSON.stringify({count:report.count, total:reviewMoney.format(report.total)}));
```

我们**展示 = [保留已经检查过的持久格式化结果](access(格式结果, "value"))**，把数据与展示来源一并交给调用者。
