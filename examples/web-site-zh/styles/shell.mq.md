使用这些自定义属性的规则应在令牌之后编译。选中文字颜色与 :root 一样保持全局，不应被框架映射限制在某张卡片中。修改值会影响整站，需核对实际 CSS 与浏览器颜色，不能只在局部重命名引用。

## _compile

| 参数 | 类型 | 默认 | 说明 |
|---|---|---|---|
| name | text | 必填 | shell.tables.md 中精确原始章节 |

| 返回 | 类型 | 说明 |
|---|---|---|
| result | text | 按原始选择器编译的单个主题区段 |

使用`name`，从站点根授予 fs.read 与 plugin。原生读取保留原始值与形态，编译器处理选择器、媒体和关键帧。这个内部工具特意保留旧壳的地址，用于比较迁移前 CSS；当前服务使用 styles/index 的明确 View 映射。缺失章节保留诊断，返回文本既不写文件，也不证明新结构已经适配。

我们 **declarations = [读取原始区段的实际声明](document.read_table(path="styles/shell.tables.md", title=`name`))**.
最后返回 *[编译原地址用于保留比较](web.make_style(name=`name`, table=`declarations`))*.

## css

| 返回 | 类型 | 说明 |
|---|---|---|
| result | text | 保持原六区段地址与级联的基准 CSS |

从站点根授权 fs.read 和 plugin，依次编译令牌、关键帧、布局、断点、引言与控件。这六段地址、顺序和连接方式保持原实现，用于原始数据与散列比较。命名属性仍可分别读取，但不额外加入本基准，以免改变原级联；它们由新的 View 入口恢复到实际目标。

当前站点不直接加载这个旧壳基准，实际样式见 styles/index。散列相同只能证明原始主题编译保留，不能证明新的选择器匹配、字体送达或移动布局正确。用 verify 的逐行比较加上真实浏览器验证，并由服务入口显式保存实际新主题。
