两种视图随请求查询应用持有的同一 articles 表。卡片使用摘要和短链，详情使用完整 Markdown 正文。构造描述不另开数据库，也不缓存启动时的旧记录；原生卡片与文章类名供原主题继续使用。

## cards

| 返回 | 类型 | 说明 |
|---|---|---|
| result | list | 通过 /post/短链 打开详情的当前文章卡片 |

构造不需要副作用。监听应用拥有数据库与实际执行上下文，卡片保留原来的稳定 id 顺序，字段仍为 title、summary 与 slug。标题、摘要按文本转义，完整正文只留给详情。公共发布或后台共享表单新增文章后，下次请求即能看见，不必重启站点。

我们 **资源 = [描述实际当前文章列表](视图.查询(源="articles", 排序="id", 链接前缀="/post/"))**。
最后返回 *[安放一个请求期间的卡片职责](组件.请求资源(值=`资源`, 槽="articles"))*。

## detail

| 返回 | 类型 | 说明 |
|---|---|---|
| result | list | 实际路径捕获选中的首篇完整 Markdown 文章 |

声明的 /post/{slug} 页面在请求解析资源时提供路径参数，同名查询字符串不能替换它。原生详情即使有摘要也使用完整正文，并且每次复制条件再替换参数，不污染启动时保留的定义。缺少数据库仍是错误；没有匹配记录沿用现有查询资源的空结果约定。

条件保留为明确记录，不能把单列表误当字典。父层继续拥有文章区域的位置，本函数不自己拼接标题或渲染 Markdown，以免与卡片规则和当前请求上下文分离。

我们 **条件 = [保留实际短链条件记录](表.设(map=None, key="slug", value="{slug}"))** 和 **资源 = [描述匹配短链的完整正文](视图.查询(源="articles", 条件=`条件`, 详情=True, 上限=1))**。
最后返回 *[安放实际请求的文章](组件.请求资源(值=`资源`, 槽="article"))*。
