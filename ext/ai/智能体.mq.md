## 提取工具名

| 参数 | 类型 | 默认 | 说明 |
|---|---|---|---|
| 回复 | any | 必填 | 待解析的模型回复，不直接作为执行授权 |

| 返回 | 类型 | 说明 |
|---|---|---|
| 结果 | any | 解析人可读调用行：`CALL:<名>` 或 `调用：<名>` / `调用:<名>`。 |

这里使用`回复`。

解析人可读调用行：`CALL:<名>` 或 `调用：<名>` / `调用:<名>`。

这里按行识别工具协议，先去掉行两端空白，再按半角冒号分隔。CALL 或“调用”作为前缀时，后面的片段成为候选工具名；没有匹配则返回空值。当前实现不把任意自然语言中的函数名当作请求，也不在这里执行函数。候选值仍要经过运行工具的白名单判断。

注意实际分隔符是半角冒号，全角冒号的示意不能保证被本函数识别。同一回复包含多个有效协议行时，后面的匹配会覆盖前面的候选；工具名中的额外冒号也不作为完整名称保留。生成端应只输出一条明确的 CALL:name，避免依赖这种兼容解析。

保留所需的文本分隔符，先**esc = [Keep the exact separator](table.put(in=None, at="nl", value="\n"))**。
得到**`nl` = [读取 nl 字段](json.get(value=`esc`, key="nl"))**。
得到**`text` = [调用 trim](trim(value=`回复`))**。
得到**`lines` = [调用 split](split(value=`text`, sep=`nl`))**。
得到**found = 空**。

- [line](遍历 `lines` 为 `line`)
  得到**`t` = [调用 trim](trim(value=`line`))**。
  得到**`parts` = [调用 split](split(value=`t`, sep=":"))**。
  得到**`n` = [调用 len](len(value=`parts`))**。
  1. `n` > 1
    得到**`head` = [调用 at](at(value=`parts`, index=0))**。
    得到**`head` = [调用 trim](trim(value=`head`))**。
    得到**`rest` = [调用 at](at(value=`parts`, index=1))**。
    得到**`rest` = [调用 trim](trim(value=`rest`))**。
    1. `head` == CALL
      得到**found = rest**。
    2. `head` == 调用
      得到**found = rest**。
    3. *
      **_ = 1**
  2. *
    **_ = 1**

完成后返回*found*。

这里使用`任务`、`写回`=True、`流式`=False、`打印增量`=False、`沙盒`=False、`沙盒配置`="default"。

原子一轮：上下文 → 大模型 → 可选子任务调工具。返回 map 记录（`status`、`task`、`decision`；成功含 `result`，可选 `tool` / `tool_result`；失败含 `error`）。默认（`写回=真`）将结果写入调用行下的命名槽 `ok` / `error`；传 `写回=假` 可关闭。

流式=真 时走 SSE；打印增量=真 边读边打印。返回 map 仍是最终 result 文本。`沙盒=真` 时结果附带沙盒配置行。

默认会写回调用文档；若只想观察结果，请显式传入写回=False，避免演示修改任务源码。这一轮先把用户任务写入当前会话历史，再用调用点上下文请求模型。流式分支先收集事件得到最终文本，普通分支直接取得回复。随后只把明确的工具协议视作调用候选；其余文字作为回答保留。中文兼容面使用模型的运行方法，并不要求调用方假装它具有英文资源的全部接口。

有工具候选时，运行工具负责核对作者白名单并等待子任务。拒绝结果进入 error 字段；成功结果被序列化后提供给模型，再形成面向用户的回答。tool_result 因而保存的是序列化文本，消费它时不要误当原始业务记录。没有工具候选时直接使用本次回复，避免重复请求。

这一步会把最终助手回复追加到同一历史，并按写回开关将完整记录放入调用点的 ok 或 error 槽。演示或只读任务应明确关闭写回，生产流程则要为实际文件操作准备权限。返回记录中的 status、decision、result 和工具字段分别说明流程状态、原始决定与最终答案，它们不能相互替代；任务特有的正确性仍由调用方验证。

这里的沙盒开关只给返回记录附加所选配置行，不会把上述模型或工具调用迁移到 CoW 环境。需要隔离试运行，应调用试跑入口或使用具有实际 CoW 执行边界的工程运行流程。不要依据 sandbox_profile 字段的存在宣称副作用已经隔离。写回失败、插件失败和传输失败仍沿既有运行诊断报告，函数没有通用事务回滚能力。

开发此方法时，先使用只返回固定文本的离线模型替身确认上下文、历史与结果字段，再分别验证工具允许、工具拒绝和写回开关。涉及真实模型的测试还应覆盖流式结束、错误事件和无文本结果。保持这两类验证分开，才能判断错误来自编排还是传输，避免用一次线上回答掩盖未执行的分支。
