本文件对应英文 form.mq.md 的服务端装配工作流，中文作者直接调用这些具名函数。独立校验、离线表单渲染与直接提交仍使用英文文件对象的 validate、render、submit，不把页面引用当成直接写入工具。字段与规则同属一个原生表单资源，页面只安放引用，服务入口显式挂载它。构造、字段更新、校验与提交需要 plugin；引用是纯计算。以下示例只构造引用，不打开数据库或提交记录。

```sh
marqdo call ext/data/表单.mq.md 引用 '标识="article"' --json
```

准备真实表单时按构造、字段、规则、文案的顺序保留每次返回的新资源，再挂载到已准备的应用。实际处理请求的是 /_form/标识 系统地址。只保护展示页面不能保护提交入口；私有表单应给挂载指定角色，并另行配置鉴权。

## 构造

| 参数 | 类型 | 默认 | 说明 |
|---|---|---|---|
| 表 | text | 必填 | 已存在的数据库业务表名 |
| 动作 | text | "insert" | 原生提交动作，例如 insert 或 update |
| 标识 | any | None | update 使用的记录标识；插入通常不指定 |

| 返回 | 类型 | 说明 |
|---|---|---|
| 结果 | any | 尚未提交的原生表单资源 |

输入`表`、`动作`="insert"与`标识`=None，调用需要 plugin。这里只创建表单资源，不建表、不插入记录，也不验证一次用户请求。继续调用字段与规则保留完整定义；实际数据库来自服务入口的应用资源。缺少原生插件或不支持的动作应保留真实诊断。

构造完成后返回 *[创建指定业务表的原生表单](form.form(table=`表`, action=`动作`, id=`标识`))*。

## 字段

| 参数 | 类型 | 默认 | 说明 |
|---|---|---|---|
| 资源 | any | 必填 | 构造返回的实际表单资源 |
| 定义 | any | 必填 | name、label、type、required 等字段记录表 |

| 返回 | 类型 | 说明 |
|---|---|---|
| 结果 | any | 带字段定义的新表单资源 |

输入`资源`和`定义`。name 应对应业务表字段；label 是展示文案，type 选择原生输入类型，required 使用布尔值。记录表用 @ 首列保持逐行结构。更新需要 plugin，返回值供规则或挂载继续使用；不提交用户输入，也不改变数据库结构。

完成定义后返回 *[将字段绑定到同一个表单](> `资源`.fields fields=`定义`)*。

## 规则

| 参数 | 类型 | 默认 | 说明 |
|---|---|---|---|
| 资源 | any | 必填 | 已有字段定义的实际表单资源 |
| 定义 | any | 必填 | field、rule、message 记录；例如 required 与 max:120 |

| 返回 | 类型 | 说明 |
|---|---|---|
| 结果 | any | 带原生校验规则的新表单资源 |

输入`资源`和`定义`。规则按字段名关联，message 是拒绝输入时显示的原因。服务端仍执行相同规则，不能只依赖浏览器必填属性。此步需要 plugin，但不会尝试插入或更新记录。保留返回值，避免挂载未携带新规则的旧资源。

规则明确后返回 *[绑定实际提交使用的校验规则](> `资源`.rules rules=`定义`)*。

## 文案

| 参数 | 类型 | 默认 | 说明 |
|---|---|---|---|
| 资源 | any | 必填 | 保留字段和规则的实际表单资源 |
| 提交 | text | "提交" | 提交按钮文字 |
| 取消 | text | "取消" | 取消链接文字 |
| 返回地址 | text | "" | 取消目标；也是原生成功提交返回地址 |

| 返回 | 类型 | 说明 |
|---|---|---|
| 结果 | any | 带按钮文字和返回目标的新资源 |

输入`资源`、`提交`="提交"、`取消`="取消"和`返回地址`=""，调用需要 plugin。文案是纯文本，不承载 HTML。显式返回地址用于成功后的跳转；没有指定时由原生请求返回路径决定。设置按钮文案本身既不授权提交，也不改变字段校验规则。

配置后返回 *[保留提交、取消与成功返回目标](> `资源`.labels submit=`提交` cancel=`取消` cancel_href=`返回地址`)*。

## 引用

| 参数 | 类型 | 默认 | 说明 |
|---|---|---|---|
| 标识 | text | 必填 | 服务入口通过挂载显式注册的系统表单标识 |

| 返回 | 类型 | 说明 |
|---|---|---|
| 结果 | map | 供组件请求资源节点安放的 form_ref 描述 |

使用`标识`引用实际挂载的表单。构造无需任何副作用，不加载插件、不注册路由，也不伪造字段或 CSRF。请求时才由原生服务读取当前会话、返回路径和同一份字段规则；未挂载的标识保留错误，不能变成空的成功表单。

声明后返回 *[引用请求时的同一个表单](form.reference(id=`标识`))*。

## 挂载

| 参数 | 类型 | 默认 | 说明 |
|---|---|---|---|
| 应用 | any | 必填 | 已准备、保留数据库与路由上下文的应用 |
| 标识 | text | 必填 | 页面引用与系统 /_form/ 路径使用的标识 |
| 资源 | any | 必填 | 保留字段、规则和文案的实际表单 |
| 角色 | any | None | None 保持公开行为；否则保护实际系统表单 GET 与 POST |

| 返回 | 类型 | 说明 |
|---|---|---|
| 结果 | any | 挂载资源与可选角色门禁后的新应用 |

使用`应用`、`标识`、`资源`与`角色`=None，在监听前授予 plugin 并保留返回的应用。挂载绑定的是明确的系统地址，不暗中注册业务页面。私有表单应指定允许的角色并配置鉴权；仅隐藏控件或保护展示页不足以保护提交。

会话存在时提交必须携带真实 CSRF，字段失败的重试页面仍保留该令牌。系统路径可通过网页检视观察，但检视不能证明数据库可写或当前用户获准提交。公开示例可以保持角色为空，生产策略由调用者明确决定。

准备就绪后返回 *[绑定实际表单处理器及其访问策略](form.mount(app=`应用`, id=`标识`, form=`资源`, roles=`角色`))*。
