网络扩展手册：先描述页面如何拆分，再写各块内容，最后预览、起站和验证。
普通 .mq.md 函数就是工具，无需另一套 Skill 编译器或工具目录。
安装用户先执行 marqdo ext add web；源码开发先用 bash scripts/build-web-plugin.sh 构建
Go 插件，必要时用 MARQDO_WEB_PLUGIN 指向其绝对路径，不能把安装根覆盖到源码 ext。

先看可执行结果

以下命令从仓库根运行；安装后把 FILE 换为安装根下对应路径。
call 的文本字面量需要保留内层双引号，会话引用必须保护美元符号。
同时检查退出码与 JSON 的 ok，再读取 result。

```sh
marqdo call ext/web/网页/索引.mq.md 布局规则 --json
marqdo call ext/web/网页/索引.mq.md 预览正文 '正文="# 可读页面"' '标题="预览"' --effects plugin --json
marqdo call ext/web/网页/索引.mq.md 预览节点 '节点=[{"type":"row","value":[{"type":"markdown","value":"## 左栏"},{"type":"markdown","value":"## 右栏"}]}]' --effects plugin --json
```

先拆布局的工程实践

首页先拆为导航、主体和页脚。页脚有左右布局，就拆成品牌栏与链接栏；链接栏若还有
双栏，再拆文档和社区。递归进行，直到内部只是简单 Markdown 能直接表示的内容。
终点是单一内容职责且不再需要内部排布，不是每段话都新建文件。

```text
site/
  index.mq.md                 Document，选择布局根
  components/index.mq.md      纵排：导航、主体、页脚
    nav/index.mq.md           一个导航职责
    nav/content.md            普通 Markdown 链接
    main/index.mq.md
    main/content.md           普通 Markdown 正文
    footer/index.mq.md        分栏：品牌、链接
      brand/index.mq.md
      brand/content.md        品牌与版权
      links/index.mq.md       分栏：文档、社区
        docs/index.mq.md
        docs/content.md       文档链接
        community/index.mq.md
        community/content.md  社区链接
  pages/about.mq.md           另一条声明路由
  api/ping.mq.md              Endpoint
  preview.mq.md               离线装配并渲染
  serve.mq.md                 启动进程，不放页面内容
```

每个父 index 只导入子块、组合子节点、选择一层布局；每个叶子 content.md 只写 Markdown。
父块出现大段正文、多种布局职责或 HTML 标签就继续拆；叶子不负责外部排列。
不应先写整页 HTML，再把这个字符串切成几个文件。默认也不靠内联 CSS 对齐。
复杂表格、表单、数据源和交互按各自职责再分模块，不能以此回填整页 HTML 壳。

```text
marqdo call examples/web-layout-handbook-zh/preview.mq.md main --effects plugin,fs.read,output.write --fs-root examples/web-layout-handbook-zh --json
marqdo call ext/web/网页.mq.md 服务 '根="examples/web-layout-handbook-zh"' --effects plugin,fs.read,network.write --fs-root examples/web-layout-handbook-zh --json
```

检查 / 首页、/about 普通文档、/api/ping JSON。首页应真的出现父子嵌套与两个页脚区域，
不是把同一组节点平铺。宽屏横排，窄屏自动折叠，无需作者手写 HTML 或 CSS。

现有五列怎样表达树

公共 View 列仍为 type、slot、value、attrs、style，中文别名为 类型、槽、值、属性、样式。
记录表首列使用 @，让输出为节点列表。父节点类型 row/column 表示几何，值列保留子表；
nav/header/footer/section/aside 表示语义区域。markdown 的值是正文字符串。
类型和值没有变成另一种私有 DSL。合并仅生成兄弟顺序，分栏才产生几何关系。
style 是类名引用，不会凭空定义 CSS；运行时内置默认布局，主题后续按独立资源处理。

最小叶子可以直接以 Markdown 文本调用组件正文。文件较长时像参考工程一样从
content.md 读取，这样原始文件无需转义字符串。父文件不用提前渲染子组件。

```marqdo
---
markup: occlusion
导入:
  组件: ext/web/网页/组件/索引.mq.md
  布局: ext/web/布局/索引.mq.md
  网页: ext/web/网页.mq.md
---

# main

**left = 组件.正文 文本="### 品牌" 槽="brand"**
**right = 组件.正文 文本="[关于](/about)" 槽="links"**
**siblings = 组件.合并 甲=`left` 乙=`right`**
**footer = 布局.分栏 子节点=`siblings` 槽="footer"**
**html = 网页.渲染 节点=`footer` 标题="分栏预览"**
> 打印 内容=`html`
```

Document、Endpoint 与运行边界

普通 Document 用 类型: 网页、路由、标题和 Markdown 正文，保留原来的静态/数据源路径。
组件 Document 另外声明 视图: main，其普通 main 函数返回节点列表；服务在启动时执行装配一次，
通过同一渲染器生成 HTML。改内容后重启。自动数据源绑定使用普通 Document，不与此启动装配混用。不要在这个装配函数里再启动服务器或调用渲染；
它返回结构即可。请求期互动放在 Endpoint，声明 类型: 端点、路径、方法、请求、响应，
主程序返回响应值。不要把启动时装配误解为自动的请求期模板绑定。

服务是长时间阻塞的生命周期操作，可用 marqdo call 直接调用，并显式授予
plugin、fs.read、network.write。需要更多资源时，在普通启动函数中顺序组合准备站点、
各资源的绑定工具与监听，并保留每次更新后的应用。网络库负责 WebSocket，安全库负责
登录与会话；准备阶段不会打开端口。网页检视给出根目录时可离线扫描声明；新进程中的空应用
不能检视另一个进程的私有路由状态。

```sh
marqdo call ext/web/网页.mq.md 检视 '根="examples/web-layout-handbook-zh"' --effects plugin --json
```

按职责打开模块

[布局](../布局/索引.mq.md)教会何时继续拆、纵排与分栏；[组件](组件/索引.mq.md)负责
Markdown 叶子与语义包裹；[页面](页面/索引.mq.md)负责句柄与离线渲染；
[路由](路由/索引.mq.md)用于高级手动声明，整站默认走 Metadata。
[文档对象模型](文档对象模型/索引.mq.md)提供内容转换，原始 HTML 仅为兼容边界。
[客户端](客户端/索引.mq.md)挂载 Marqdo WASM，业务交互继续使用 lib/browser；
[能力](能力/索引.mq.md)只诊断原生加载。[门面](../网页.mq.md)保留服务、渲染、检视和应用 API。

[页头资源](../页头.mq.md)保留真实 SEO、字体与资源声明，能用于离线预览；它不会成为正文或片段占位。数据查询、表单引用和会话导航仍在真实请求中解析，继续沿用五列 View。完整中文实践见 [网络站点入口](../../../examples/web-net-site-zh/index.mq.md)。

开发路线与验收

先尝试组合现有 Markdown、纵排、分栏。新增原语才修改 plugins/web/internal/artifact
与 ABI 导出，普通页面不要新增宿主原语。保持双语入口与五列结构，参数契约紧跟标题，
返回契约也在首条执行语句之前。## 只能用于真正工具，普通说明保持叙述段落。
新增文件时更新 src/ext_cli.rs 安装清单。修改 Document 启动装配要保留普通文档与 API 的行为。

```text
marqdo call skills/marqdo-dev/index.mq.md test 'targets=["web_handbook"]' --effects plugin --fs-root . --require-ok --json
marqdo call skills/marqdo-dev/index.mq.md test 'targets=["call_cli"]' 'filter="web_"' --effects plugin --fs-root . --require-ok --json
marqdo call skills/marqdo-dev/index.mq.md test 'targets=["gold"]' 'filter="ext_web"' --effects plugin --fs-root . --require-ok --json
```

手册门禁直接执行本包双语 sh 围栏与作者程序，另外预览并启动参考工程，核对路由、
嵌套结构和 API。叙述比例只作最低门槛，清单不能无条件发放“通过”。
当前没有自动把任意网页拆成组件的功能，也没有靠样式列实现完整 CSS 编译器。
布局仍是作者的显式设计决定，这些入口与运行证据帮助 AI 遵守它。

## 建站手册

| 返回 | 类型 | 说明 |
|------|------|------|
| result | any | Development workflow and stopping rule |

返回建站流程与拆分终点，不执行文件操作，也不声称已经验收某个站点。
先建立区域树，再写父组件与 Markdown 叶子，最后按声明路由启动并测试。

这张表返回工程步骤与停止条件，供作者安排实现顺序；它不会自动创建目录、拆分现有页面或替站点完成验收。先确定区域树，把首页拆成导航、主体与页脚。若页脚有品牌栏和链接栏，再拆子区域；链接有文档与社区两栏时继续拆分。父文件只表达一层布局，叶子只保留可直接阅读的 Markdown 内容。

区域树稳定后，首页用 Document 元数据声明路由并选择装配入口。其他页面各自声明路由，接口逻辑放到 Endpoint，使请求期间的业务计算与启动时的页面装配各有归属。不要在返回组件的函数里启动服务器，也不要把启动时运行一次的装配误当作每次请求都会执行的数据绑定。

实现过程中先离线预览，核对实际父子节点和区域内容；再从站点目录启动服务，检查首页、普通文档和 API 的真实响应。浏览器还需验证宽屏分栏与窄屏折叠。只看清单文本、返回固定 ready 或将整页 HTML 分成几个字符串文件，都不能证明已实现统一的文档架构。若某个块仍需独立内部排列，就返回布局拆分阶段继续细化。

`workflow` =

| key | value |
|-----|-------|
| goal | build a site as executable documents |
| step_A | draw region tree before content |
| step_B | recursively split components to Markdown leaves |
| step_C | declare home Document and view main for composed structure |
| step_D | declare more Documents with their own routes |
| step_E | declare Endpoint handlers for request-time work |
| step_F | run serve.mq.md from the site directory |
| step_G | compare preview and live output; test routes and browser geometry |
| stopping_rule | one Markdown responsibility and no internal layout |

完成后返回*workflow*。

## 预览正文

| 参数 | 类型 | 默认 | 说明 |
|---|---|---|---|
| 正文 | text | "" | Markdown content |
| 标题 | text | "Preview" | Document title |

| 返回 | 类型 | 说明 |
|------|------|------|
| result | text | HTML document |

这里使用`正文`=""、`标题`="Preview"。

离线渲染 Markdown `正文`=""，默认 `标题`="Preview"。
此工具只返回 HTML 文本，不写文件、不注册路由。复杂页面先拆布局，
不要用整页原生 HTML 字符串冒充正文。需要原生插件。

完成后返回*[调用 渲染](网页.渲染(正文=`正文`, 标题=`标题`))*。

## 预览节点

| 参数 | 类型 | 默认 | 说明 |
|---|---|---|---|
| 节点 | list | 必填 | Nested View rows |
| 标题 | text | "Preview" | Document title |

| 返回 | 类型 | 说明 |
|------|------|------|
| result | text | HTML document |

这里使用`节点`、`标题`="Preview"。

渲染已经按职责拆分的 `节点`，默认 `标题`="Preview"。
父节点的值继续持有子节点，叶子值为 Markdown；返回 HTML 不会启动服务。
与真实 Document 的装配使用同一渲染器，能检查双栏是否确实保留了层级。

完成后返回*[调用 渲染](网页.渲染(节点=`节点`, 标题=`标题`))*。
