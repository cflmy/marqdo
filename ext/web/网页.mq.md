门面模块：从[中文根手册](网页/索引.mq.md)选择业务路径。
布局先拆成父组件与 Markdown 叶子，默认不写整页 HTML。构造值与启动进程是两件事；
下面示例从生产者开始，所有句柄沿同一会话传递，渲染时才需要原生插件。

```sh
marqdo call ext/web/网页.mq.md 渲染 '正文="# 文档"' '标题="预览"' --effects plugin --json
marqdo call ext/web/网页.mq.md 检视 '根="examples/web-layout-handbook"' --effects plugin --json
```

页面结构用五列 View 记录，父值保留子表。纯布局、DOM 构造和客户端描述无需插件。
整站服务可通过 marqdo call 直接调用服务函数，也可在普通启动函数中组合准备、资源绑定与监听；检视磁盘站点请给出根目录，不能从新进程
读取另一个进程的私有应用。结构化 Document 使用 视图: main，在启动时执行布局装配。

开发时先复用组件和布局模块，再改对应领域实现；保持中英入口与真实契约一致。
验证 web_handbook 与既有 Web Artifact 金样，资源、鉴权和网络能力不要塞回门面。

| 参数 | 类型 | 默认 | 说明 |
|---|---|---|---|
| 标题 | text | "" | 文档标题 |
| 路由 | text | "/" | 路径 |
| 方法 | text | "GET" | HTTP 方法 |
| 正文 | text | "" | Markdown 正文 |
| 节点 | any | None | View 表或 None |
| 数据源 | text | "" | 表名 |
| 排序 | text | "" | 如 -created_at |
| 条件 | text | "" | col=val 列表 |

| 返回 | 类型 | 说明 |
|------|------|------|

这里使用`标题`=""、`路由`="/"、`方法`="GET"、`正文`=""、`节点`=None、`数据源`=""、`排序`=""、`条件`=""。

构造 Document 句柄，默认 `标题`=""、`路由`="/"、`方法`="GET"、`正文`=""、

`节点`=None、`数据源`=""、`排序`=""、`条件`=""。站点页面优先用 `类型: 网页`
Artifact，由 `服务` 发现；本工具供预览或程序化构造。节点必须是统一 View 表，
不是 HTML。

完成后返回*[调用 page](web.page(title=`标题`, route=`路由`, method=`方法`, body=`正文`, nodes=`节点`, data_source=`数据源`, data_order=`排序`, data_where=`条件`))*。

## 检视

| 参数 | 类型 | 默认 | 说明 |
|---|---|---|---|
| 应用 | any | None | 完成显式资源绑定后保留的当前应用 |
| 根 | text | "" | 可选的元数据扫描目录；给出时优先于应用 |

| 返回 | 类型 | 说明 |
|---|---|---|
| 结果 | map | scope、declared 与 system；区分文件声明和当前应用的实际处理器注册 |

使用`应用`=None、`根`=""，应明确选择观察范围。准备应用并绑定资源后，把保留的应用交给检视，再开始监听。清单复用真实服务的路由注册流程，后加的 WebSocket、JSON 查询、表单、登录、后台和静态挂载都会出现，不读取已经过期的启动快照；冲突注册保留原生诊断。

给出根目录时只扫描 Artifact 元数据，不执行启动函数或页面，因此不能观察这些函数运行后才绑定的资源。scope 为 metadata 表示文件声明与运行时模板，为 registered 表示传入应用的实际处理器注册。它们都不能证明已经监听、数据库可用或登录成功。

需要 plugin。此操作不调用请求处理器、不创建或重置会话、不打开数据库、不启动监听，也不返回凭据和无关应用字段。系统清单包含实际配置的表单、片段及会话路径；已有来源信息的声明仍保留文件身份，便于继续阅读实现。

完成后返回 *[观察当前声明及运行时注册](web.inspect(app=`应用`, root=`根`))*。

| 返回 | 类型 | 说明 |
|------|------|------|
| result | any | 服务结果 |

这里使用`根`="."、`主机`="127.0.0.1"、`端口`=18081、`数据库`=None、`静态目录`=""、`中间件`=None。

扫描 `根`="." 下 `类型: 网页|端点` Artifact，注册声明路由并在 `主机`="127.0.0.1"

## 准备站点

| 参数 | 类型 | 默认 | 说明 |
|---|---|---|---|
| 根 | text | "." | 含网页与端点声明的站点目录 |
| 主机 | text | "127.0.0.1" | 监听地址；准备阶段不开启端口 |
| 端口 | number | 18081 | 交给稍后监听阶段使用的端口 |
| 数据库 | any | None | 已有数据库资源 |
| 静态目录 | text | "" | 站点内的可选静态资源目录 |
| 中间件 | any | None | 可选安全响应头表 |

| 返回 | 类型 | 说明 |
|---|---|---|
| result | map | 已发现路由并完成启动布局装配的应用资源 |

这里使用`根`="."、`主机`="127.0.0.1"、`端口`=18081、`数据库`=None、`静态目录`=""和`中间件`=None。准备阶段发现 Document 与 Endpoint，执行一次启动布局，但不启动监听。随后把应用交给网络、鉴权等资源的绑定函数，并保留每次返回的新应用，最后调用监听。原始站点的绝对根目录随应用保留，因此端点回调和静态资源的相对路径仍按站点解析。目录读取和布局执行可能在打开端口之前失败，应保留原始诊断。

完成准备后返回*[发现站点并保留其资源上下文](web.prepare(root=`根`, host=`主机`, port=`端口`, db=`数据库`, static_dir=`静态目录`, middleware=`中间件`))*.


## 监听

| 参数 | 类型 | 默认 | 说明 |
|---|---|---|---|
| 应用 | any | 必填 | 准备站点后已完成资源绑定的应用 |

| 返回 | 类型 | 说明 |
|---|---|---|
| result | map | 阻塞的原生监听结果 |

输入`应用`后才启动已配置的主机和端口。可以在普通可调用启动函数中按顺序准备站点、绑定资源、监听，再通过 marqdo call 执行该函数。监听持续占用当前进程，由调用者或测试监督进程负责停止。显式授予启动流程所需的插件、文件读取与网络写入权限；返回一个应用描述本身不会启动后台服务。

最后返回*[在保留的站点根目录中启动服务](web.listen(app=`应用`))*.



## 编译样式

| 参数 | 类型 | 默认 | 说明 |
|---|---|---|---|
| 名称 | text | 必填 | 原生类选择器名，可含后代选择器尾部 |
| 属性 | any | 必填 | 属性、值两列的声明式主题表 |

| 返回 | 类型 | 说明 |
|---|---|---|
| 结果 | text | 原生样式编译器输出的 CSS 文本 |

使用`名称`与`属性`，授权 plugin。该入口对应英文 make_style，把可读属性表交给已有原生编译器；不接收整页 HTML，也不创造另一套布局语言。名称应由作者控制，对应 View 的样式类与原生内容结构。返回文本不会自动写入或挂载文件，调用者需显式选择生成路径并以原生文件能力保存。

纯属性构造不需要插件，真正编译才在这里加载原生实现。属性值的格式或选择器错误保留真实诊断，不能替换为旧产物继续声称已构建。动态业务数据不应该用来拼接选择器；测试应比较实际编译结果并查看对应区域的渲染效果。

完成编译后返回 *[使用已有主题编译器处理声明](web.make_style(name=`名称`, table=`属性`))*。
