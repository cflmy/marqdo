布局决定 Marqdo 网站是否可维护。首页不是一整块 HTML，而是目录上的 Document 与
组件文件：导航、侧栏、主区、底栏。若某一区仍复杂（例如底栏双栏品牌+链接），继续
拆文件，直到每个文件单一职责、一张 View 表或短 Markdown。值、库字段、具名样式
只通过 `|类型|槽|值|属性|样式|`（或英列名）绑定。不要用 `dom.raw` 或大段 CSS
「先做完」——那会绕过绑定，事后不可读。

设计正文：`doc/design/ext-web-layout-paradigm.md`。

## 给智能体

若你只拿到本文件，写站前先拉取规则。布局规则工具本身是纯函数，可不加
`--effects plugin`；后续渲染/服务必须加。

调用示例（纯文本）：
  marqdo call ext/web/布局/索引.mq.md 规则 --json
  marqdo call ext/web/布局/索引.mq.md 视图契约 --json

撰写时先建 `components/*.mq.md`（可再嵌套），再写瘦的 `类型: 网页` 页面声明路由
与主区意图。用合并节点拼接 View。禁止把 `dom.raw` 当作首页主实现。

*None*

## 规则

返回布局工程规则映射，供智能体与验收清单使用。无参数。

| 返回 | 类型 | 说明 |
|------|------|------|
| result | any | 规则表 |

*> layout.rules*

## 视图契约

返回唯一允许的 View 列名（英文）。中文别名为 `类型|槽|值|属性|样式`。无参数。

| 返回 | 类型 | 说明 |
|------|------|------|
| result | any | 列名列表 |

*> layout.view_schema*

## 合并节点

拼接 View 节点表 `甲` 与 `乙`。区域拆文件后，用本工具组装而不写 HTML。

| 参数 | 类型 | 说明 |
|------|------|------|
| 甲 | any | 第一张 View 表 |
| 乙 | any | 第二张 View 表 |

| 返回 | 类型 | 说明 |
|------|------|------|
| result | any | 合并后的节点 |

*> layout.merge_nodes a=`甲` b=`乙`*

## 验收组件

文档门：传入组件 `名`（文件名）与单一职责 `职责`（一句话）。返回验收行，提醒
必须保持单一职责。不写磁盘。

| 参数 | 类型 | 说明 |
|------|------|------|
| 名 | text | 组件名，如 导航 |
| 职责 | text | 单一职责描述 |

| 返回 | 类型 | 说明 |
|------|------|------|
| result | any | 验收行 |

*> layout.accept_component name=`名` duty=`职责`*
