工程实践：先画区域树，再建立对应目录，最后写内容。首页拆成导航、主体、页脚；
页脚拆成品牌和链接；链接如果仍有双栏，就拆成文档与社区。内部还需要独立排布就继续拆，
直到叶子只含简单 Markdown。不是把每个句子拆成文件，而是消除同一个叶子中的多种职责。

真实文件树在[参考站点](../../../examples/web-layout-handbook/index.mq.md)。
父 index.mq.md 只导入、组合子块并选择一层布局；叶子 content.md 是普通 Markdown。
不要先写 HTML 壳再拆文件，那会把结构依旧藏在字符串里。

```sh
marqdo call ext/web/布局/索引.mq.md 规则 --json
marqdo call ext/web/布局/索引.mq.md 分栏 '子节点=[{"type":"markdown","value":"左栏"},{"type":"markdown","value":"右栏"}]' '槽="页脚"' --json
```

分栏会在现有五列表的值中保留子节点，渲染为可响应的 CSS 网格；窄屏自动折叠。
纵排保持区域从上到下的顺序。样式列是类名引用，不是一段 CSS 规则，也不会自动定义主题。
只用合并工具会得到相邻节点，不会得到双栏。内容叶子使用组件正文，语义包裹使用组件包裹。

开发与验收：每个叶子应能以内容职责命名；父文件出现大量正文或 HTML 标签时继续拆。
先用页面渲染离线检查，再运行参考站点，核对首页、关于页与 API。
新增结构需修改 plugins/web/internal/artifact 并同步双语工具与 web_handbook 测试。

## 规则

| 返回 | 类型 | 说明 |
|------|------|------|
| result | any | 布局实践约定 |

返回先拆布局、递归到 Markdown 叶子的工程约定。无参数；
规则是说明，不声称已静态审查某个文件。真正验收需要运行并检查站点。

*> layout.rules*

## 视图契约

| 返回 | 类型 | 说明 |
|------|------|------|
| result | list | View 列名 |

返回五个公共列名。子块通过值列继续包含同样的 View 记录；
不增加第二种布局表方言，也不把任意属性名解释为 CSS。

*> layout.view_schema*

## 合并节点

| 参数 | 类型 | 说明 |
|------|------|------|
| 甲 | list | 第一组节点 |
| 乙 | list | 第二组节点 |

| 返回 | 类型 | 说明 |
|------|------|------|
| result | list | 兄弟节点 |

拼接 `甲` 与 `乙`，只保留顺序，不增加几何关系。
需要横向排列时使用分栏，需要上下分区时使用纵排。

*> layout.merge_nodes a=`甲` b=`乙`*

## 纵排

| 参数 | 类型 | 说明 |
|------|------|------|
| 子节点 | list | 子块列表 |
| 槽 | text | 父区域名 |
| 样式 | text | 可选类名 |

| 返回 | 类型 | 说明 |
|------|------|------|
| result | list | 父容器节点 |

为 `子节点` 声明一层上下顺序。默认 `槽`=""、`样式`=""。
父块只负责排列，内容和更深层结构留在导入的子组件。结果仍是 View 节点列表，
可以继续传给祖先组件或页面渲染，无需提前转为 HTML。

*> layout.stack children=`子节点` slot=`槽` style=`样式`*

## 分栏

| 参数 | 类型 | 说明 |
|------|------|------|
| 子节点 | list | 子块列表 |
| 槽 | text | 父区域名 |
| 样式 | text | 可选类名 |

| 返回 | 类型 | 说明 |
|------|------|------|
| result | list | 父容器节点 |

为 `子节点` 声明一层响应式多栏。默认 `槽`=""、`样式`=""。
父块只负责排列，内容和更深层结构留在导入的子组件。结果仍是 View 节点列表，
可以继续传给祖先组件或页面渲染，无需提前转为 HTML。

*> layout.columns children=`子节点` slot=`槽` style=`样式`*

## 验收组件

| 参数 | 类型 | 说明 |
|------|------|------|
| 名 | text | 组件名称 |
| 职责 | text | 单一职责描述 |

| 返回 | 类型 | 说明 |
|------|------|------|
| result | any | 待人工或测试核对的清单 |

为 `名` 与 `职责` 返回待检查的条目。仅依据这两个文本无法证明组件合格，
所以结果明确标注为清单，调用者仍须检查文件内容与渲染结果，不自动发放通过标签。

*> layout.accept_component name=`名` duty=`职责`*
