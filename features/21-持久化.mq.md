调用 main 需要 process.exec,fs.write，并将 --fs-root 指向仓库根目录。这是本页明确声明的文件修改，普通阅读不会写文件。静态 View 与可调用函数使用同一份源码，输出来自实际执行。

## main

| 返回 | 类型 | 说明 |
|---|---|---|
| result | map | Result：保存到本页 total 槽位的实际文本 |

静态快照把执行输出嵌入 HTML；显式写回则把选定结果保存在源码的命名槽位里。本页正是需要后者的活文档示例，调用者应先知道会修改本页，再授予 fs.write。写回后的值可以在普通 Markdown 源码和差异中审阅，不依赖仍存活的外部进程。

金额由原生开发指南计算，随后共享例程只调用 Node Intl 完成固有库尚未提供的本地化货币展示。例程检查每次求值并关闭其持久内核，调用者得到的已经是普通文本。没有 Python 编排，也没有外部文件写入器；保存动作继续使用 Marqdo 的 writeback。示例的金额为 950，当前区域设置下的文本为 ¥950.00，真实输出会成为下面的 total 槽位内容。

再次执行替换同一个键，不重复添加槽位。若解释器不可用或格式化失败，在写文件之前就返回真实失败；固有文件策略或 IO 错误也保留诊断。这里持久化的是已经选定的文本，不保存任意内核内存，也不能根据它重建活资源句柄。完成后可用正常的仓库差异审阅流程检查变更，再决定是否随文档提交。

面向读者的发布页面通常选择静态快照；明确需要在源码中保存最新运行结果的审计文档才使用写回。两者可以共存，但静态导出如果执行了本页，仍会尊重这个显式写回操作。权限不会因为文档外观而被隐式扩张，依赖步骤也不能在失败后继续伪造结果。
