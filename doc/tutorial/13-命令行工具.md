# 第 13 章：命令行工具

Marqdo 提供一组命令行工具，覆盖运行、浏览、调试、发布全流程。

## 13.1 命令总览

```text
marqdo --version                 # 查看版本
marqdo run 文件.mq.md            # 运行程序
marqdo view 路径                 # 文档浏览器（默认端口 7429）
marqdo debug 路径                # 调试界面（默认端口 7430）
marqdo catalog 路径 -o 目录      # 生成 OKF 风格清单
marqdo sync 路径 -o 目录         # catalog 的别名
marqdo ext list                  # 列出扩展
marqdo ext add llm|agent|web|quantum
marqdo ext remove llm|agent|web|quantum
```

## 13.2 运行程序：`run`

```bash
marqdo run hello.mq.md
```

指定后端（树遍历默认 / 字节码）：

```bash
marqdo run hello.mq.md --backend bytecode
```

### 错误诊断

诊断信息格式：`path:line:col: message`（行 / 列从 1 开始）。

```text
error: hello.mq.md:5:1: undefined variable `x`
```

根据 `path:line:col` 定位并修复，再重新运行直到退出码为 0。

## 13.3 文档浏览器：`view`

`view` 启动一个本地文档浏览器，把 `.mq.md` 渲染成可浏览的文档站：

```bash
marqdo view public --no-open
```

浏览器打开后可看到：

- Structure（结构）
- 函数大纲 / 搜索
- Execution（执行）
- Variables（变量浮窗）

## 13.4 调试器：`debug`

```bash
marqdo debug public --no-open
```

提供独立调试页面，支持：

- 断点
- 单步执行
- 局部变量查看

## 13.5 生成清单：`catalog` / `sync`

从源码派生 OKF 风格的 YAML / Markdown 知识包：

```bash
marqdo catalog public -o .marqdo
# 或
marqdo sync public -o .marqdo
```

| 参数 | 默认 | 说明 |
|------|------|------|
| `PATH` | `.` | 工程根或含 `.mq.md` 的目录 |
| `-o` / `--out` | `.marqdo` | 输出目录 |

产物：`catalog.yaml`、`index.md`、`modules/*.md` 等。

## 13.6 扩展管理：`ext`

```bash
marqdo ext list
marqdo ext add llm
marqdo ext add agent
marqdo ext remove llm
```

扩展默认安装到 `~/.marqdo/ext`（或 `MARQDO_EXT`）。

## 13.7 标准库与可执行文件解析

- **标准库**：内置于二进制；磁盘 `lib/` 或 `MARQDO_LIB` 可覆盖。
- **库路径解析**：`MARQDO_LIB` → 当前目录 `lib/` → 可执行文件旁 `lib/`。

## 13.8 证明定理表：`prove`

知识文件里带定理表（`| 定理 | 结论 | 前提 | 策略 |`）的函数，可以用
`marqdo prove` 生成 Lean 4 证明并自动判定真假：

```bash
marqdo prove 审批.mq.md               # 生成 Lean 模块 + 判定（有 Lean 时）
marqdo prove 审批.mq.md --json        # 智能体可读的单个 JSON 报告
marqdo prove emit 审批.mq.md          # 只生成不判定
marqdo prove audit 审批.mq.md         # 只审查可证子集，不写盘
marqdo prove --all skills/            # 目录模式：逐文件出证，整体取最差
marqdo prove clean                    # 清空 .marqdo/prove
```

状态从强到弱：`proved`（Lean 证出）> `checked`（离线符号执行关闭）>
`unverified`（超出可证子集，诚实未知）> `rejected`（子集验收拒绝）>
`unproved`（反例）> `error`（判定层错误）。关键纪律：

- **没有 Lean 也能跑**：离线符号执行给出 `checked`，但它不是 proved——
  只是"在受限片段里符号地关掉了"。状态如实降级，绝不冒充证明。
- **假定理必须红**：断言与执行语义矛盾的定理会得到反例（路径见证，
  如 `金额 = 10001`），退出码 1。
- **单调性护栏**：离线说 `checked` 但 Lean 证不出（或反过来）→
  `error[proof.divergence]`，判定器缺陷优先于任何绿灯。
- **证书缓存**：判定结果按源码+计划+库+版本哈希缓存于 `.marqdo/prove/`，
  重复运行毫秒级命中；`--no-cache` 绕过。

详见 [design/prove-cli.md](../design/prove-cli.md)（命令面、可证子集与判定管线）。
