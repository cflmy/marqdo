# 一、你现在这份代码最大的问题

你的代码本身没有明显的工程性错误，真正的问题是**抽象泄漏**。

例如现在用户最终会写：

```marqdo
**answer = > llm.complete prompt=`prompt` stream=`stream` echo=`echo`**
```

而内部又出现：

```marqdo
url = [base_url](self) + [suffix](self)
auth = [bearer](self) + [api_key](self)
headers = > table.put ...
messages =
| @ | role | content |
...
body = > json.stringify ...
resp = > net.http_post ...
```

这实际上是在把：

* HTTP
* Authorization
* OpenAI endpoint
* JSON
* messages
* stream
* SSE

全部暴露给了 Marqdo 的 AI 编程层。

这和“代码即文档”是有冲突的。

因为用户真正想表达的是：

> **“请让这个模型回答这个问题。”**

而不是：

> “请构造一个 OpenAI Chat Completion HTTP 请求。”

# 二、我建议把 `ext/ai/llm` 重新定义成一个「LLM Object」

我会把整个设计提升一个抽象层：

```text
                    ┌────────────────────┐
                    │   Marqdo Document  │
                    └─────────┬──────────┘
                              │
                         llm.ask()
                              │
                 ┌────────────┴────────────┐
                 │                         │
             Context                   Policy
                 │                         │
                 └────────────┬────────────┘
                              │
                         LLM Runtime
                              │
                 ┌────────────┼────────────┐
                 │            │            │
              OpenAI        Ollama       Other
            Compatible    Compatible    Provider
```

然后整个 `ext/ai/llm` 应该分成 **四层**：

### Layer 1：Semantic API

用户真正使用：

```text
llm.ask
llm.generate
llm.stream
```

### Layer 2：Conversation / Context

处理：

```text
system
context
user
assistant
tools
```

### Layer 3：Model abstraction

处理：

```text
provider
model
temperature
max_tokens
```

### Layer 4：Transport

才处理：

```text
HTTP
JSON
SSE
Authorization
/chat/completions
```

**第 4 层应该尽可能不可见。**

# 三、最重要的变化：`complete` 不应该成为主要 API

我甚至建议把：

```text
complete
```

降级成内部 primitive。

因为：

> `complete` 是 API Client 的语言，而 `ask` 是 AI-native language 的语言。

这是一个非常重要的区别。

用户应该看到：

```marqdo
**answer = > llm.ask prompt=`prompt`**
```

而不是：

```marqdo
**answer = > llm.complete prompt=`prompt`**
```

甚至进一步，我希望 Marqdo 最终能够做到：

```marqdo
**answer = > llm.ask**
```

然后让当前文档本身成为 prompt。

这样才真正开始出现“代码即文档”的味道。

也就是说：

> **Prompt 不再只是字符串，而是 Knowledge Artifact。**

这和你之前“Executable Document → Executable Knowledge Base”的方向是完全一致的。

# 十、第三个重大变化：不要让 `stream` 是一个 Boolean

你现在：

```marqdo
stream=False
```

这是典型 API Client 设计。

我建议把它提升成能力：

```text
llm.ask
llm.stream
```

而不是：

```text
llm.complete stream=True
```

所以：

```marqdo
**answer = > model.ask prompt=`prompt`**
```

表示：

```text
一次性得到结果
```

而：

```marqdo

```

表示：

```text
得到事件流
```

然后：

```marqdo
**answer = > llm.reduce events=`events`**
```

把 stream 转换成最终结果。

这样语义非常清晰。

# 十二、第四个重大变化：Result 应该是对象，而不是裸字符串
