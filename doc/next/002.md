这可能是你整个项目最重要的一次“闭环”。

> `.mq.md` = Markdown + 可执行程序 + 知识。

> `.mq.md` = Agent 学会的经验。

于是：

```text
            Agent
              │
              │ 学习

          .mq.md
```

这就非常有意思了。

**Agent 的 memory 不再是一段向量 embedding，也不只是聊天历史。**

它是：

> **可阅读、可修改、可验证、可执行的知识程序。**

这才是真正的 **Marqdo-native Agent**。

# 7. 这甚至给你提供了一个极漂亮的学习曲线

假设一个任务第一次需要：

```text
8 次 LLM calls
```

第二次：

```text
5 次
```

第三次：

```text
3 次
```

学习完成：

```text
0 次
```

或者：

```text
1 次 small model
```

这时候你就有一个非常漂亮的指标：

## Reasoning Amortization

定义：

$$
C_n =
\frac{
\text{LLM inference cost over first } n \text{ executions}
}{n}
$$

随着执行次数增加：

```text
Cost
 │\
 │ \
 │  \
 │   \
 │    \____
 │         ─────────
 └───────────────────
        executions
```

**这甚至解决了你之前担心的 Marqdo 性能难以证明的问题。**

你之前不知道怎么证明：

> Marqdo 比 Python 更适合 AI。

但现在你可以研究：

> **Marqdo Agent 能否把高成本 LLM reasoning 逐渐编译成低成本 executable knowledge？**

这个是一个非常明确、可测量、而且很有研究价值的问题。

# 8. 但是这里有一个非常重要的危险

你说：

> “超过三次调用就自动总结。”

我建议：

**不要真的这么简单。**

三次可以作为：

> **触发学习候选**

但不能作为：

> **自动认为已经学会。**

否则会发生：

```text
第一次：特殊情况
第二次：特殊情况
第三次：特殊情况
```

LLM 总结：

```text
General rule:
...
```

然后把偶然性错误“编译”进 Skill。

这会非常危险。

# 9. 我建议建立“经验 → 技能”的四阶段

## Stage 1 — Episode

每次任务产生：

```text
task
context
actions
tool calls
observations
errors
result
cost
```

例如：

```text
episode-001.mq.md
episode-002.mq.md
episode-003.mq.md
```

---

## Stage 2 — Candidate Skill

达到阈值之后：

```text
3+ similar episodes
```

让 LLM 总结：

```text
candidate.mq.md
```

但它还是：

> **candidate**

而不是正式 skill。

---

## Stage 3 — Verification

用历史任务重新运行：

```text
episode 1
episode 2
episode 3
```

测试：

```text
candidate skill
```

如果：

```text
3 / 3 success
```

再加新的 held-out task：

```text
episode 4
```

如果：

```text
4 / 4
```

才提高 confidence。

---

## Stage 4 — Compilation

最后：

```text
candidate
 ↓
verified
 ↓
compiled
```

此时才允许：

```text
llm_free = true
```

你目前的系统已经有 `llm_free` 命中后直接运行 resource 的机制。

我认为未来这个 flag **不应该是人工/静态指定的属性，而应该成为学习系统的产物。**

# 10. 甚至可以让 mq.md 自己记录“学习程度”

比如：

```yaml

success_rate: 0.941
llm_free: true
created_from: 6c8...

---
```

然后正文：

```markdown
# CSV 成人用户筛选

## Intent

筛选年龄大于 18 岁的用户。

## Procedure

- 读取 CSV
- 判断 age
- 过滤
- 排序

如果无法确定 age 字段：

> ask_llm

| Case | Result |
|---|---|
| case-001 | ✓ |
| case-002 | ✓ |
| case-003 | ✓ |
| case-004 | ✓ |
```

注意这个设计里非常重要的一点：

> **Skill 本身可以包含一个 fallback 到 LLM 的路径。**

所以不是：

```text

```

而是：

```text
确定部分 → deterministic
不确定部分 → small model
真正未知 → full LLM
```

这就非常接近人类的实际认知过程。
