---

## 1. 动机

今日 [`objects.md`](../design/objects.md) 明确非目标：**继承 / 接口 / 可见性**。  
实际扩展（如 `# agent` / `# llm`）靠「再写一个对象 + 组合句柄」，缺少：

- 复用父构造 / 父方法而不复制 `.mq.md`  
- 子类型在 `_type` 链上解析方法  
- 与 Markdown 标题体系一致的、可读的继承声明

需要一种**不引入 `class`/`extends` 关键字**、且与现有 `=`（绑定）与 `>`（调用）语义兼容的写法。

---

## 2. 锁定语法（提案）

```markdown
# 子类 = > 父类
```

| 片段 | 既有含义 | 组合后含义 |
|------|----------|------------|
| `# 子类` | 定义对象 / 类型 | 子类型名 |
| `=` | 绑定 / 赋值 | 类型关系写在「类型定义槽」上 |
| `> 父类` | 调用（此处为类型名） | **基类引用**（不是构造实例） |

可选带参基类（若基类本身是泛化构造，v1 可暂不支持）：

```markdown
# 特化智能体 = > 智能体
```

中英对称：

```markdown
# Child = > Parent
# 子类 = > 父类
```

### 2.1 为何不冲突

1. **今日** `# 名` 后接的是构造体正文，不是 `` `# 名 = …` `` 标题行。  
2. **语句绑定**是 `*…*` 或行内 `` `x` = ``，不是 ATX `#` 标题。  
3. **`> 父类` 在标题行**出现在 `=` 右侧：解析器可把「`#` 标题含 `=` 与 `>`」识别为**类型声明**，而非执行构造。  
4. 真正构造实例仍是正文或 `# main` 里的 `` `x` = > 子类 … ``。

反例（仍是今日语义，不变）：

```markdown
# main

*`a` = > 父类 *
```

---

## 3. 运行时语义（草案）

### 3.1 方法解析

实例 map 仍有 `_type` = 构造时的类型名（子类名）。

查找 `` `obj`.方法 ``：

1. 在 `_type` 对应对象上找 `## 方法`  
2. 未找到 → 沿 **基类链** 查找  
3. 仍无 → 报错（带类型链）

构造：

1. 若子类构造体未显式处理，可先调基类构造（见开放点：是否自动 `super`）。  
2. 返回 map 的 `_type` = **最具体子类名**（不是父类名）。

### 3.2 子类正文

```markdown
# 工蜂 = > 智能体

## 采蜜
    + `花`

*`out` = > `self`.step task=`花` *
**`out`**
```

- 子类可定义新 `##`  
- 可覆盖同名 `##`（子类优先）  
- 站立提示 / 字段约定：文档层说明，v1 不引入可见性关键字

### 3.3 多继承

**v1 不支持。** 一个 `# 子 = > 父` 仅一条基类。混入用组合（句柄字段）而非多 `>`。

## 4. 解析与 AST

标题形态需在 [markdown-mapping.md](../design/markdown-mapping.md) / parse 中新增一种 object decl：

| 字段 | 值 |
|------|-----|
| `name` | 子类 |
| `base` | 父类（标识符） |
| `body` | 与今日 object body 相同 |

歧义处理：

- `# Foo = 1` → **非法**（右侧必须是 `> 类型名`）  
- `# Foo = > bar.baz` → v1 **非法**（基类须为已定义对象名，不走任意调用表达式）  
- 基类尚未定义 → Pass1 收集后解析；循环继承报错

---

## 5. 与标准库 / 扩展

| 用途 | 例子 |
|------|------|
| 扩展官方智能体 | `# 客服 = > agent` / `# 客服 = > 智能体` |
| 扩展 llm 句柄 | 一般不必要；优先组合 |
| 用户域模型 | `# 订单服务 = > 服务基类` |

官方 `lib/*` 仍以自由函数为主；继承主要服务 `ext/` 与用户对象。

---

## 6. 推荐落地顺序

```text
I0  语法 + AST + 金样（解析/循环继承错误）     ✅
I1  方法解析沿基类链；构造 _type=子类           ✅
I2  覆盖方法；文档更新 objects.md               ✅
I3  （可选）子构造约定：显式 > 父类 … 或隐式 super
```

验收：

1. 无继承文件行为不变。  
2. 子类实例能调父类 `##`；覆盖后只走子类。  
3. `` # A = > B `` / `` # B = > A `` 诊断清晰。  
4. Skill / 金样：`tests/structure/inherit-*.mq.md`。

---

## 7. 开放点

1. **隐式 super**：子类构造体执行前是否自动跑父构造体？  
   - 建议 v1：**不隐式**；需要时正文写 `` `self` = > 父类 … `` 再改字段，或提供 `` > 父类.构造 … `` 约定。  
2. 中英基类别名：`> agent` 与 `> 智能体` 是否同一对象（取决于模块导出）。  
3. 继承是否写入 OKF Module 页（catalog 展示 `extends`）——可随 O3/O4 增强。

---

## 8. 非目标

- 接口 / 抽象方法 / 可见性（`public`）  
- 多继承、mixin 关键字  
- 用继承替代 `plan` 工作簿接力  
- 把 `# 子 = > 父` 解析成「定义时立即构造父实例」
