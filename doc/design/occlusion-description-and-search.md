# 遮蔽描述与参数化检索：编译器不内置词表

| | |
|---|---|
| 状态 | **Proposed · 待批准**（描述自由文本 · 检索由调用方传词 · 空载荷 warning） |
| 日期 | 2026-10-22 |
| 提出 | 用户：允许 LLM 的"假接通"，但描述里写清；**为什么不直接让 LLM 传关键词来检索** |
| 修正 | ①**删除内置词表**，检索参数化 ②**空载荷一律 warning**（写 `None` 即消除） |
| 前置 | [occlusion-syntax.md](occlusion-syntax.md) |

---

## 0. 四条定调

1. **`[]` 里是纯粹的描述文字，对执行没有任何作用。**
2. **编译器不内置任何词表。** 检索是**调用方传参**：`--grep 待开发,未实现`。
   LLM 想搜什么就传什么，随时可换。
3. **空载荷一律 warning**：`()` 为空说明"这段遮蔽里没有可执行内容"。
   修法很简单——写 `None` 或一个实际返回值。
4. **强力推荐 LLM 申报**：写不了真接口就"申报"，别"假装"。这要进 agent 提示词。

一句话：

> **描述给人读；检索词由调用方给；空着不写会被提醒。**

---

## 1. 为什么允许「假接通」

模型被要求"接入搜索"时，最省力的是写个返回固定值的函数，然后声称已接通。

| 处理方式 | 结果 | 问题 |
|---------|------|------|
| **A 禁止**（"不许伪造"） | 模型改用更隐蔽的伪造 | 不可检测、不可计数 |
| **B 放任** | 静默假功能 | 文档撒谎，没人知道欠了多少 |
| **C 申报**（本方案） | 允许，但写进描述 | 代码照跑；欠据可数、可查 |

C 的关键：**不改道德要求，改激励**——申报比伪造省力，且申报后代码照样跑。

## 2. `()` 内部语法定稿

### 2.1 取元

| 语义 | 写法 |
|------|------|
| Map 取成员 | `at(表, 键)` |
| List 第 n 项（1-based） | `at(列表, 1)` |
| 缺键取默认（不崩） | `get(表, 键, 默认值)` |

### 2.2 调用

| 形态 | 写法 |
|------|------|
| 位置实参 | `加一函数(31)`（逗号可选：`加一函数(31 2)`） |
| 具名实参 | `计税(档位=2, 金额=100)` |
| **带空格 callee** | `加一 号(31)` → callee = 第一个 `(` 之前的全部文本 |
| 库路径 / 方法 | `txt.str_trim(s)` / `obj.方法(x)` |

实测：`加一 号(31 )` → `32`；`> 加一 号 31` → `unknown function 加一`。
**`(` 是明确分隔符**——这是缺陷 D8 的结构性解法。

### 2.3 循环

```markdown
- [从篮子里取出的每个果子](遍历 篮子 为 果)
```

### 2.4 空载荷：**一律 warning**

```markdown
[某某功能，还没做]()      # ⚠️ label.empty_payload
```

| 写法 | 结果 |
|------|------|
| `[功能，开发中]()` | ⚠️ warning |
| `[功能，开发中](None)` | ✅ 无警告（显式声明返回值） |
| `[功能，开发中](json.parse text="[]")` | ✅ 无警告 |

**为什么一律报**：空 `()` 意味着"什么都没写"。哪怕桩，也该说明它返回什么——
`None` 也是一个答案，而且**下游能据此判断**。

**为什么不会造成存量噪音**：遮蔽语法是新形式，**今天仓库里没有一处**，
所以这条 warning 不可能产生历史债（与 stale 检查不同）。

## 3. 描述与检索

### 3.1 描述是自由文本

```markdown
[某个功能，没开发完成]()
[某某功能开发中](None)
[按 `税率` 与 `档位` 计算应缴税额](…)
```

唯一约束：**不能为空**（`[](…)` → `label.missing`，error）。
`[]` 不参与执行、类型、作用域。

### 3.2 编译器**没有**词表

编译器只做两件事：

1. 原样保存描述字符串
2. 提供**参数化检索**：你给词，我搜

```bash
marqdo labels search --grep 待开发,未实现,开发中      # OR 匹配
marqdo labels search --grep 接口 --json               # 任意词，含上下文
marqdo labels search --grep 待开发 --count            # 只数数
```

MLSP 对应方法：

```json
{ "method": "labels.search", "params": { "grep": ["待开发","模拟"], "json": true } }
```

### 3.3 为什么不做内置词表

| 理由 | 说明 |
|------|------|
| **词表是语义偏见** | "什么算未完成"是项目判断，不该由编译器规定 |
| **词表永远不全** | `开发中` / `未接` / `待联调` / `占位` / `TODO`…追不上真实语言 |
| **闭集要改编译器** | 新词得发版；而 LLM 每天都在造新表述 |
| **分类该在查询期，不在编译期** | 编译器保持"哑"，查询保持"聪明"——这是更干净的架构 |
| **LLM 更会挑词** | 它知道自己在说什么（"接口未接通" vs "待开发"），传参即可 |

**你这一问是对的：词表是冗余层。** 删掉它，编译器少一个概念，用户多一分自由。

### 3.4 唯一的代价：CI 需要一个"什么算欠债"的定义

没有词表，`--count` 就不知道该数什么。解法**不是**把词表放回编译器，而是：

> **让项目在调用处声明**——通常就写在 CI 脚本里（天然可版本化、可评审）。

```bash
# CI：把"未完成"定义在调用点，编译器不需要知道
marqdo labels search --grep "待开发,未实现,开发中,模拟,桩" --count \
  --baseline .marqdo/pending.json --fail-on-increase
```

- 词集在**仓库里可读、可改、可评审**
- 换成别人的项目，词集跟着换，编译器一行不改
- `--baseline` + `--fail-on-increase` = 棘轮（只拦新增，不追旧账）

### 3.5 检索语义（v1）

| 项 | 规则 |
|----|------|
| 匹配方式 | **子串匹配**（CJK 无词边界，子串最稳） |
| 多词 | OR（任一命中） |
| 大小写 | 英文不敏感 |
| 输出 | 文件、行号、描述原文、`()` 代码、命中词 |
| 误判 | 必然存在（`[不属于待开发范围]` 会命中），但**只影响计数**；输出带原文，人可判断 |

**不做否定语法**。若实际误判过多，再加「否定词窗口」（`不再|无需|非` + 词 → 不计）作为 v1.1 可选项。

## 4. 桩的语义

### 4.1 三条规则

| # | 规则 | 原因 |
|---|------|------|
| 1 | **桩必须能跑**（不得报错） | 否则整篇文档被阻断 |
| 2 | **桩必须写明返回什么** | 空载荷 → warning；写 `None` 也行，但不能什么都不写 |
| 3 | **桩不得被当成已完成** | 描述里申报状态；检索能查到 |

### 4.2 桩返回什么

| 手段 | 写法 |
|------|------|
| 显式空值 | `[某某功能开发中](None)` |
| 常量占位 | `[税率预报，模拟](0.1)` |
| 假数据 | `[搜索结果，模拟](json.parse text="[]")` |
| **桩 + 契约（推荐）** | 配合返回契约声明类型 → 桩是"有类型的洞" |

```markdown
## 搜索

| 返回 | 类型 | 说明 |
|------|------|------|
|  | list | 命中列表（当前未接） |

[按关键词检索，接口未接，模拟](json.parse text="[]")
```

### 4.3 惯例（不强制）：桩返回值带 `stub: true`

```markdown
[ERP 推送，模拟](json.parse text={"ok":true,"stub":true})
```

## 5. 工程化：把「申报」变成习惯

### 5.1 写进 agent 提示词（强烈推荐）

```text
当你要接入一个你无法真正接入的能力时：
1) 不要静默伪造，也不要声称已完成。
2) 用遮蔽语法写出该能力，并在描述里写明状态，例如：
     [按关键词检索，接口未接，待开发](None)
     [搜索结果，模拟](json.parse text="[]")
3) 桩必须能跑（不得报错），并写清返回值（写 None 也比空着好）。
4) 收尾前用 labels.search 自查：还有多少处写了未完成？
```

**为什么对 LLM 有效**：它把"编造"变成"填表"——模型不必判断"这算不算伪造"，
只需写出状态词并给一个返回值。

### 5.2 LLM 可用的工具面

| 工具 | 用途 |
|------|------|
| `labels.search --grep 词集 --json` | 自查/盘点（任意词） |
| `labels.search --grep 词集 --changed` | 只看本次变更涉及的 |
| `labels.search … --count` | 只取数字（省 token） |
| MLSP `labels.search` | 同上，协议内 |

### 5.3 工程指标

| 指标 | 怎么算 |
|------|--------|
| `pending_count` | `labels search --grep <项目词集> --count` |
| `unlabeled_empty` | `label.empty_payload` 的 warning 数 |
| `stub_ratio` | pending 数 / 遮蔽总数 |
| `stub_age` | 需 VCS（可选，不进默认路径） |

## 6. 生命周期

```
① 写桩    [按关键词检索，接口未接，待开发](None)
                ↓
② 盘点    labels search --grep 待开发 → 列出它
                ↓
③ 开发    换成真实 HTTP 调用
                ↓
④ 复核    去掉"待开发"字样、改写描述
                ↓
⑤ 数字-1  检索结果自动减少
```

### 6.1 stale 豁免：也由调用方决定

没有词表，就不能"内置判定谁豁免"。所以：

| 方式 | 说明 |
|------|------|
| `check --stub-words "待开发,模拟"` | 命中这些词的遮蔽**跳过 stale** |
| MLSP `validate { "stub_words": [...] }` | 同上，供 agent 回路用 |
| 不传 | 不豁免（所有遮蔽都参与 stale 检查） |

**默认不传**：宁可先严格，让用户显式选择豁免词。
这也和"参数化"一致——**豁免也是调用方的判断**。

### 6.2 防"做完了忘去掉申报"

- `labels search --grep <词集> --changed`：本次变更中被改过的桩
- 会话末汇总带一行 `pending_touched: 2`（只给数字）

## 7. 与防疲劳机制的协同

| 机制 | 作用 |
|------|------|
| 桩可豁免 stale（调用方传词） | 12 个桩不会变成 12 条常驻警告 |
| 债务用**棘轮**（`--baseline` + `--fail-on-increase`） | 老债不阻塞、新债立刻拦 |
| 检索是**按需命令**，不进 `check` 人类输出 | 零噪音 |
| 搜不到**不报错** | 描述自由，机器不纠正用词 |
| 空载荷 warning 只针对新语法 | **不可能产生历史债** |

## 8. 编译器实现点

| 位置 | 要做的事 |
|------|---------|
| `src/parse` | 解析 `[描述](实现)`，**原样保存描述**（不解析、不分类） |
| `src/ast.rs` | `Expr::Occluded { label: String, inner: Option<Box<Expr>> }` |
| `src/label.rs`（新增） | 描述**索引与检索**（子串、OR、大小写不敏感）；L1 引用一致性；T1 前后对比 |
| `src/check.rs` | 三条：`label.missing`（error）、`label.ref_dangling`（error）、`label.empty_payload`（**warning，一律**） |
| `src/interp.rs` | 描述**不影响求值**；空载荷 → `None` |
| `src/main.rs` | `marqdo labels search --grep … [--json/--count/--changed]`、`marqdo check --stub-words …` |
| `src/mlsp.rs` | `labels.search`、`validate.stub_words`、会话汇总 `pending_touched` |
| `src/view/render.rs` | 遮蔽渲染：描述为正文、实现可折叠 |
| `doc/` | 教程补"描述 + 检索 + 申报习惯" |

**关键**：编译器**不含任何词表常量**。搜什么、豁免什么，全由调用方给。

## 10. 风险与取舍

| 风险 | 说明 | 缓解 |
|------|------|------|
| 子串误判 | `[不属于待开发范围]` 会命中 | 只影响计数；输出带原文；否定词窗口留 v1.1 |
| CI 需要维护词集 | 词集散落在脚本里 | 建议集中成一行，写进 `scripts/`；可评审 |
| 词集不一致 | 不同脚本用不同词 | 约定一份 `scripts/pending-words.txt`（**项目自定，编译器不管**） |
| 空载荷 warning 过多 | 作者爱留空 | 修法极简（写 `None`）；且只影响新语法 |
| 桩腐化 | 忘去掉申报 | `--changed` + 会话汇总，不做常驻警告 |
| 假功能上生产 | 最坏情况 | `view` 显著标记；CI 可用 `--count` 门禁 |
