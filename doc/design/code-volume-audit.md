## 5. 与设计的关系

精简的目的不是数字好看，而是**不让冗余掩盖设计**：

- 已消除的都是**重复实现**（同一逻辑多份 → 必然漂移）
- 保留的都是**单一实现的特性能耐**
- 每一条删改都跑全量测试：`605 → 609 passed / 0 failed`，编译零警告

如果后续还要压体量，正确的方向是**砍特性**（例如 `view` 的调试面板、`formula` 引擎），
而不是继续在特性内部找"重复"——那已经找完了。
