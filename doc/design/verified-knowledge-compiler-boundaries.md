# Marqdo 可验证知识编译器：目标、可信边界与阶段性验收

> 状态：设计决策 + 当前实现对应。形成于 2026-11-18 关于知识编译、Lean 自动证明边界、AI 智能体知识沉淀与模块化组合的讨论。
>
> 本文规定目标边界，不以“任意 Marqdo 程序都能被 Lean 证明”为目标。具体实现应以当前源代码、真实 Lean 证书与 CI 结果为准；不能通过修改文档把尚未验证的语义宣布为已证明。

## 1. 问题与共同认识

Marqdo 的核心目标不是取代 Lean，也不是成为全自动程序验证器：

> 代码即文档，文档即知识库，知识即可执行。

更严格的工程定位：

> 将人类可读文档编译为**可寻址、可验证、可执行、可复用的知识制品**的语言与编译系统。

其中，“可验证”不是“所有性质都能被形式化证明”；“知识即可执行”也不是“所有外部世界事实都有数学定理”。

形式证明必然面临不可判定性、求解器资源上限、环境非确定性、外部依赖以及不完整的语义模型。即使 Lean 内核确认一个命题正确，它确认的也是**给定 Lean 定义及假设下的命题**。如果 Marqdo 源码到 Lean 定义的映射未建立可信性，该证明不能无条件提升为 Marqdo 运行时正确性。

因此，整个设计遵守四条约束：

1. **证明精确标注作用域**：明确对象、输入域、效应、数值模型及前提；不要将模型证明冒充完整运行时证明。
2. **可证明则证明**：在受支持且能建立可信模型的子集内，由真实 Lean 内核验证；失败不得降级成虚假的 proved。
3. **不能证明仍可成为知识**：保留测试、执行轨迹、实验数据、来源与未经验证的假设；这些证据不等价于逻辑证明。
4. **不会静默取得执行权**：锚点引用、知识收据、定理声明或插件假设都不自动执行工具、授权访问环境或改变运行时行为。

## 2. 三层可信性，不由一个 Lean 布尔值代替

### L1：结构与来源验证——基础必需

对象包括 Markdown/Marqdo AST、唯一锚点、符号和模块解析、精确调用绑定、源码与契约指纹、引用有效性、依赖闭包、过期证据识别。

主要由解析器、SemanticProject、知识图谱、哈希与回放机制验证，无须假装数学证明。

### L2：形式证明——限定作用域

对象包括函数前/后置条件、调用前提、符号路径、算术结论、可组合的跨模块性质。

Lean 执行核验；Rust 只能生成目标、提前拒绝以及绑定真实源码，不能凭主机端的计算结果自行宣称定理成立。

### L3：执行和经验验证——不可省略

对象包括插件和 API 调用、量子硬件实验、非确定性智能体决策、实际数据质量与第三方网络服务。

应携带可复现测试、日志、测量、环境版本和来源，不应自动转化为 Lean proof。

量子科研例子：门矩阵幺正性可以有形式证明，具体设备的实验保真度必须由观测数据和校准记录支持；两种证据可组合引用，但不能互相冒充。

## 3. 证据等级（Proof is not a Boolean）

知识制品采用与旧版 \`status\` **正交**的 \`evidence.grade\`。已在 \`src/knowledge/evidence.rs\` 建立类型化模型：

| 证据等级 | 含义 | 禁止的推断 |
|---|---|---|
| \`proved\` | 目标语言、输入域及其运行时语义对应已得到可信证明 | 不覆盖未纳入证明的插件、浮点或硬件 |
| \`model_proved\` | Lean 核验了明示抽象模型下的命题 | 不得称为全部 Marqdo 运行时正确 |
| \`tested\` | 存在真实、可追溯的测试/实验结果 | 通过测试不等于数学证明 |
| \`assumed\` | 明示的外部假设、作者/插件契约 | 不得自动变成 proved |
| \`unknown\` | 未建立证据、超时、求解失败或超出可证子集 | 不等价于“命题错误” |
| \`refuted\` | 已提供可信反例 | 单纯 Lean proof 失败不能判为 refuted |
| \`stale\` | 当前源码、依赖或证明环境改变导致证据失效 | 不得复用旧证书 |

**关键规则**：

- \`proved\` 必须同时要求具体语义对应与内核证明，不能通过修改 JSON 证据字段获得。
- 目前整数算术的 Lean \`Int\` 定理通常属于 \`model_proved\`。Marqdo 的 \`number\` 契约可能包含 \`Num\`、\`Formula\` 等，且 i64 溢出、动态类型转换与异常行为尚未普遍与 \`Int\` 对齐。
- \`tested\`、\`assumed\`、\`refuted\` 的证据需要**相应来源**；不能因为某个测试通过、表格声明或求解失败就随意升级。
- 证据等级用于解释保证性质；\`usable\`、\`kernel_replayed\` 和 \`current_source_verified\` 是独立的可用性/核验状态，不能混淆。
- 知识检索、智能体与工具链看到 \`unknown\` 或 \`assumed\` 时，可以请求额外验证、执行测试、询问外部系统或拒绝高风险动作，但不能修改证明结论。

## 4. 统一契约组合：通用的是机制，不是自动化证明能力

函数契约规范化为 \`requires / ensures / effects / evidence\`，每个契约绑定明确的 \`SymbolId\`、源码来源和依赖身份。

一般调用 \(g(x)=f(a(x))\) 的组合义务：

1. **被调函数确实满足自己的已声明契约**：有可信的源码与证据绑定。
2. **调用点满足前提**：从调用方条件和实参绑定证明 \`requires_f(a(x))\`；不得把任意声明当成假设。
3. **组合后调用方结论成立**：使用被调函数的已证保证、调用方实际执行流和路径条件，向 Lean 提交调用方定理。
4. **失效传播**：源码、签名、接口、契约或依赖证明改变，旧证书不可继续使用，除非新的实现已经重新满足相应保证。

\`src/knowledge/unified.rs\` 是统一入口，逐个从当前 Marqdo AST 降级受支持的纯函数，按静态导入 DAG **自底向上**生成独立 Lean 模块。每个模块定义源派生函数并证明该函数自己的契约；调用方导入已经编译的下游模块，以其契约定理为假设链的可验证依据，既不添加 \`axiom\`，也不内联下游源码。生成的每个模块均单独通过 Lean 内核，证书绑定：

- 精确的源语义身份与传递依赖闭包；
- 受支持的源码表达式及控制结构；
- 模块生成次序、导入关系、源码摘要和已编译 Lean 摘要；
- 工具链版本及受限证明作用域。

\`marqdo knowledge replay\` 必须重读当前源文件，重新生成这些模块与依赖，再独立编译并逐项比较，不能仅仅读取带有 \`proved\` 标记的本地 JSON。

旧有常量、参数投影、表达式后端的证书仍可重放；新证明优先走统一管线，避免把多个实现拼成互相矛盾的证明状态。

### 当前统一后端的精确定义

当前实现接受：

- 静态、无副作用、跨文件的纯函数调用与有限、无环调用图；
- 参数完整、必要且无默认值；源代码参数、签名和调用点均匹配；
- 整数字面量、形参/局部变量、加减、一元负号，以及在支持的片段内由常数参与的乘法；
- 顺序局部赋值、直接返回、具有显式 \`else\` 且每条分支都返回结果的普通条件分支；
- 每个函数一个可识别、无条件、以 \`结果\` 为左侧的受限数值比较契约（等于或简单大小比较）；
- 多次静态调用与递归依赖**图上的多层模块**，由证明模块的拓扑顺序组合。

当前实现**不接受**：

- 循环、递归、非终止、并发、隐式/动态分派、插件副作用、没有可信模型的异常；
- 任意表达式值、除法/浮点/公式数值、未核验的运行时整数范围、缺省或非位置实参；
- 需要证明前置条件却没有调用方路径桥接证据的**条件契约**（可先由 \`proof-deps --verify\` 生成/检验独立义务；不能直接用无条件契约代替）；
- 非穷尽分支、分支后复杂状态合并、无法静态绑定的调用、未覆盖的语句类型；
- 任何企图把 \`model_proved\` 直接提升为全语言 \`proved\` 的操作。

这个子集提供真正的**组合机制**，不宣称任意 WP 自动求解、全部 Marqdo 运行时对应、完整 Hoare Logic 或未限制的程序正确性。

## 5. 还需要开发哪些内容、哪些明确不需要

### 当前阶段必需（完成后可停止无界扩张）

1. 所有源文件上的可寻址索引、定理证据与版本来源绑定有效。
2. 一个可用的静态契约组合通路，而非恒定返回、形参返回、算术返回三套互不兼容的证明规则。
3. 在明示纯函数子集中支持符号实参、顺序组合、基本条件分支、多层静态模块组合。
4. 真 Lean 证书独立重放与完整负例护栏（假结论、来源变化、未解义务、插件、溢出风险）。
5. 可查询的 \`evidence.grade\`，让智能体区分证明、模型证明、测试、外部假设、未知与过期。
6. 编译、知识索引、原有运行命令和解释器不发生回归。

### 扩展按需求逐步添加

- 对实际量子算法或标准库有价值的归纳、循环不变式、递归终止、特殊数据类型、插件实现见证；
- 更大范围的契约谓词、复杂路径 WP、数值类型收窄和溢出条件；
- 与真实外部测量、实验数据和 agent 轨迹对接的可复现证据。

### 当前明确不作为完成门槛

- Lean 对所有 Marqdo 代码自动证明；
- 为每个外部 API、未知插件、远程服务或量子硬件建立形式语义；
- 完整并发语义、全部递归及任意循环的自动终止证明；
- 把不可判定问题或自动证明超时当成系统故障；
- 把抽象模型的可证明性与真实环境事实的真实性混为一谈。

**阶段完成**指有明确的支持清单、严格的拒绝行为、自动 CI 与不夸大的证据等级，而不是新增语言特性就继续追逐无限泛化。

## 6. 智能体视角：知识制品应怎样使用

对 agent 的安全接口不应只返回 \`true/false\`，而应返回：

- 地址：\`SymbolId\` / 锚点；
- 执行接口：签名、前置条件、效应权限；
- 逻辑保证：受支持契约及其 \`proof_scope\`；
- 证据：\`grade\`、来源、版本、独立重放状态；
- 未解决义务：待证谓词、未建模效应、需要测试/实验的事实；
- 依赖闭包与失效原因。

智能体可以优先选择 \`model_proved\` 且输入满足限制的算法片段；在真实科研设备/外部系统调用上，同时查询 \`tested\` 证据与 \`assumed\` 的安全边界。过期制品不得直接复用。

这体现 Marqdo 的原创价值：**文档直接成为知识身份、工具接口、形式契约和执行证据的共同承载体**，而不是简单把 Markdown 文字翻译成另一种程序语言。

## 7. 验收清单与真实 CI

核心命令：

\`\`\`bash
marqdo knowledge compose --strict --json .
marqdo knowledge replay <generated-certificate> --json .
marqdo knowledge proof-deps --verify --json .
\`\`\`

\`.github/workflows/modular-proof-smoke.yml\` 用真实 Lean 核验统一契约的模块组合和独立重放；\`.github/workflows/knowledge-proof-full-gate.yml\` 跑旧版证明、知识关联、可执行知识和差分测试。

正例至少包含：跨文件纯函数证明、符号参数、两次连续调用、三层静态模块导入、穷尽分支以及调用方不等式结论。反例至少包含：假契约、修改传递依赖、重放过期证明、模糊签名、未支持运算、动态/外部调用、非穷尽分支，以及错误的证据等级提升。

任何失败、缺少 Lean、证书与源码不一致、依赖过期或不支持的语义都必须显式拒绝出证或返回未核验状态。运行中的 CI 和缓存报告不能代替最新提交的核验结果。

## 8. 结论

Marqdo 知识编译的合理完成形态是 **Verified Knowledge Compiler（可验证知识编译器）**：

> 能证明的知识生成可复用的形式证明；不能证明的知识保留明确证据与假设；所有知识均可统一寻址、依赖追踪、组合与执行，永不把未证明的内容伪装成已证明。

证明的是**明确作用域中的性质**，可信性依靠**证据分级、语义对应、来源追踪与受控执行**共同建立。这个目标可验收、可维护，也适合智能体与量子科研应用的发展方向。
