## 1. 修了什么

四件事，一句概括：**`(…)` 现在是一等调用外形**。

| # | 前 | 后 |
|---|----|----|
| 1 | `加(31)` 报 `unknown function 加(31` | ✅ 调用，返回 32 |
| 2 | 末个位置实参会吞掉 `)` | `)` 是**参数终止符** |
| 3 | 只支持空白分隔 | 支持 `,` / `，` 可选分隔 |
| 4 | 嵌套 `加(加(1 2), 3)` 不可用 | ✅ 递归解析 |
| 5 | `加一 号(31)` 不可用（D8） | ✅ **callee 可含空格** |

实测（1.5.2 本地构建，tree 与 bytecode 双后端结果一致）：

```
空格参=3        加(1 2)
逗号=3          加(1, 2)
嵌套=13         加(加(1 2), 10)
带空格callee=32 加一 号(31)      ← 缺陷 D8 的结构性解法
库函数=x        txt.str_trim("  x  ")
具名=3          加(a=1, b=2)
```

## 2. 实现要点

### 2.1 参数扫描：深度感知 + `)` 终止

`split_first_token` 与 `find_next_arg_boundary` 改为**通用扫描器**：

- 跟踪 `()` `[]` `{}` 嵌套、`"…"` 字符串、`` `…` `` 反引号
- **顶层** `)` / 空白（以及括号形里的 `,`）终止当前 token，且**不吞掉终止符**
- 字符串内的逗号不受影响（`拼接("a,b", "c")` 仍是 2 个参数）

### 2.2 `try_paren_call`：callee = 第一个 `(` 之前的全部文本

```rust
let Some(open) = s.find('(') else { return Ok(None) };
let callee_tok = s[..open].trim();          // 允许空格
```

**安全护栏**（否则会误判）：

| callee 里出现 | 判定 |
|--------------|------|
| `=` | 不是括号调用（那是 `text=a(b)` 具名实参） |
| `[` `]` `(` `)` `"` `'` | 不是括号调用（那是 `trim [stdout](…)` 方括号实参） |
| 以 `[` `]` `"` `'` 开头 | 不是括号调用 |
| 反引号 | **允许**（保留 `` `obj`.方法(…) `` 接收者写法） |

### 2.3 表达式级 postfix 调用

`parse_primary` 的裸词分支：**紧跟** `(` 时按调用解析。

```rust
if self.allow_paren_call && self.rest().starts_with('(') { … }
```

要求"紧跟"（不隔空格），使 `加 (1)` 仍是原来的"文本 + 括号"行为。

### 2.4 方括号形也允许空格 callee

`is_bracket_callee_inner` 不再拒绝空白：`[加一 号] 31` 可用。
（仓库内可执行的方括号调用用量为 0，风险极低。）

## 3. 关键设计决策：括号形 vs 空格形的参数**值**语义不同

这是本里程碑唯一有争议的点，必须写清。

| 形态 | 参数值 | 例子 |
|------|--------|------|
| **括号形** `f(…)` | 表达式（**允许** `name(args)` 调用） | `加(加(1 2), 3)` |
| **空格形** `> f k=v` | 文本（**不允许**裸 `name(args)` 变成调用） | `source=print(2+2)` 仍是文本 |

**为什么必须区分**：`source=print(2+2)` 在 Marqdo 里历来是**文本**（未加引号的实参按文本处理）。
若不区分，它会变成对 `print` 的调用，`foreign.run_lang` 直接报 `source must be text`
—— 这正是本次回归测试抓到的 3 个失败。

实现：`Parser` 增加 `allow_paren_call` 字段；`parse_call_arg_value_mode(input, prefer_var, allow_call)`
统一两种值解析（`allow_call=false` 即旧行为）。

## 6. 边界（本里程碑不做）

| 项 | 说明 |
|----|------|
| 逗号仅在括号形生效 | 空格形 `text=a,b` 的逗号仍是文本（兼容） |
| `加 (1)`（空格后跟括号） | 不视为调用，保持旧行为 |
| 遮蔽语法 `[描述](…)` | M2 才引入，本里程碑不解析 |
| 位置实参顺序脆弱性 | 与叙述顺序绑定，M7/M8 再处理（诊断） |
