## 1. 审阅结论与规范关系

Marqdo 的优势不在于给传统程序换一套 Markdown 符号，而在于：**读者解释知识、作者修改知识、程序执行知识、AI 查找并复用知识，能够指向同一份有结构的文档和其中的同一步。** 标题、叙述、表格、链接描述、输入输出、来源及执行行为不应分散在彼此手工同步的系统中。

现有规划没有放弃这一目标，但工程排序存在偏移：把身份、图、证据、锁、句柄、晋升全部铺完，再验证人和 AI 是否更容易使用。这样可能交付一个功能齐全的制品管理系统，却让文档作者承担另一套注册、声明、审核和配置工作。需要改变交付方法，不必推翻确定性编译、绑定和权限机制。

本指导规定**为何开发、作者维护什么、怎样证明值得开发**；详细规范规定语义模型与执行约束；路线图规定当前缺口、切片与完成证据。三者不是三套平行设计。遇到冲突，依次采用：`009` 的产品意图 → 本指导对作者负担、场景分级和交付次序的修订 → 详细规范的工程规则 → 附属概念示例。当前代码与测试证明“已实现什么”，不能把代码局限升级为永久语言禁令；原始讨论保留，不据其重新引入已被否决的方案。

### 1.1 方向修订清单

| 容易偏移的做法 | 修订后的要求 | 必须保留的技术约束 |
|---|---|---|
| 先做完整知识治理平台，再给作者使用 | 从一篇可读、可运行、可定位步骤的文档交付，逐层扩展 | 每个已支持路径都有准确的目标和效应边界 |
| 为进入知识库再写 YAML、注册表和索引 | 从源码推导；只有不能推导的领域事实才需作者补充 | 生成物有版本，可重建，可检查来源 |
| 所有逻辑先封装成可登记函数/类 | 一次性逻辑直接写；需要命名、解释或复用时逐步提取 | 作用域、形参、返回与副作用明确 |
| 所有调用先审核、锁定、签发远程凭据 | 本地探索、项目复用、严格业务、远程执行分级 | 精确目标、运行时权限不能被标签或模型绕过 |
| AI 只能搜文档、填工具参数 | AI 可以读步骤、组合、选择候选、局部修改、提取和验证 | 模型的选择必须转成显式目标，由编译器校验 |
| 为“独特”拒绝普通调用或新增更多标记 | 保留简单 payload；让 Markdown 结构提供程序之外的信息 | 无第二套表达式文法，无裸词隐式执行 |
| 核心构造数量不增长就是简单 | 同时检查上下文例外、记忆负担和诊断成本 | 新构造需 ADR；不靠把新规则藏进旧构造绕过审查 |

### 1.2 四个不能互相替代的完成条件

1. **读得懂**：不打开生成图，也能从源文件看出目的、关键步骤、参数角色和限制。
2. **执行同一件事**：标签表达意图，payload 决定计算；运行 trace 能回到源码步骤，不能执行另一个同名目标。
3. **改得动**：人或 AI 能修改一个明确步骤，看到影响与验证结果，不必重写整份文档或同步多份签名。
4. **复用得对**：找到已有能力后实际调用它；不满足条件时给出具体拒绝原因，而非用复制源码掩盖失败。

“更适合 AI”是待验证的产品假设，不是 Markdown 文件后缀自动赋予的性质。正确性和作者成本优先于 token 下降；错误复用更便宜不算优化。

## 2. 语法审查的保留、修正与暂缓

以下裁决针对审查结论的适用范围，不重写历史实验记录。旧文档中的原型、性能数值和当时的 `Value`/AST 限制，不能直接当作 v2.1 的规范或测试结果。

| 审查材料 | 保留的洞见 | 需要修正的外推 / 本轮处置 |
|---|---|---|
| [函数即命名](function-as-naming-philosophy.md) | 从正文计算出发，命名应降低理解和复用成本；避免无意义包装 | “具名给值缺失”是历史观察，当前有具名参数；替换模型是教学解释，不意味着禁止递归、前向引用或必须文本展开 |
| [方括号作为标签](bracket-as-label-evaluation.md) | 描述与 payload 共址；标签帮助解释、检索和拆步骤 | Classic 冲突是迁移历史，不据此恢复默认 `[键](集合)`；不强制每个常量或子表达式都有标签 |
| [圆括号与可读调用](paren-call-and-readable-invocation.md) | 调用标记应明确；保留 `f(args)` 的局部可读性 | 原型撤回不代表现有版本缺少该能力；Marqdo 的独特性不依赖消灭熟悉的表达式形式 |
| [从标记推导调用](call-syntax-from-marks.md) | 语义成分有明确标记；自然语言是连接与解释，不参与猜测调用 | 持久跨文档接口优先具名实参；短而稳定的位置参数仍合法。推断参数的声明次序变化属于接口变化，不承诺任意润色都无影响 |
| [环境参数](ambient-parameters-evaluation.md) | 参数来源应可见，避免调用者隐式环境影响复用 | 文档顶部已否决 L0 裸“执行”触发，正文旧建议不能重新生效；文件级常量也须有明确绑定与依赖，不变成动态作用域 |
| [函数作为值](functions-as-values-evaluation.md) | 区分名称数据、一等函数、有限查表；避免无需求增加核心复杂度 | “匿名函数必不能索引”“动态调用必然破坏契约”不是普遍定理。将来可研究稳定节点身份与运行时契约；本轮不引入闭包，也不永久禁止 |
| [函数作为表格](function-as-table-semantics.md) | 数据表几何有既定含义；契约表不可另造一份参数声明 | 不把表格全部变成函数，也不把“现有实现不支持”写成“表格不能计算”；有限决策表先评估库方案，只有明确角色和歧义测试后才讨论语言扩展 |
| [核心表面](core-surface.md)、[分层](layers.md) | 核心小、标记可解释、构造有测试与准入流程 | 清单中的旧取元/循环说明需随迁移更新；固定数量不等于低认知成本，守卫通过也不证明文档语义正确 |
| [链接设计](link-syntax.md)、[告警疲劳](warning-fatigue-control.md) | 单一 payload 文法；标签漂移可提示；默认安静、按需严格 | 标签不是纯粹可丢弃的注释，也不是事实证明；不做每次运行重复的批准仪式，不靠词汇相似度证明描述与代码一致 |

### 2.1 继续冻结的语法边界

- 默认 `[]()` 是描述包裹 payload；旧取元只能在显式历史兼容路径下解释。现行取元用 `access(...)` 等已支持形式；循环使用明确遍历载荷。
- `[]()` 不等于“仅函数调用”：计算、取元、调用、遍历、叙述引用都需要各自语义角色，不能只收集 call 边就宣称完成知识步骤。
- 正文引用与可执行位置有不同调度权限。普通句子不因出现“执行”“发送”或工具名而运行；正文解析成引用也不自动求值。
- 不把所有 `#` 解释成某种知识对象，或把继承悄悄变成实例关系。标题的既有语义必须兼容，IR 可区分 Type、Entity、Fact、Function。
- 不给同一参数增加正文声明、签名表、工具 schema 三套作者真相。规范签名和工具 schema 是投影；契约表补充类型、约束和说明，不偷偷增加形参。
- 可读源文件是硬要求；普通 Markdown 渲染器是否把含空格/嵌套表达式的链接渲染成可点击链接是另一件事。不能承诺全部标准渲染器理解执行语义。

### 2.2 哪些编辑不能当成“只是改文案”

不含语义标记的普通叙述润色，应保持执行结果和实现摘要；标签改名应保留 payload 行为，但更新展示/检索内容。反引号声明、首次出现顺序、标题名称/层级、粗斜体、表格几何、契约、来源和适用范围的改变则可能影响程序或知识可信性。编辑器必须展示真实差异，不能统一标为 prose-only。

标签漂移诊断应说明“描述或实现可能需要复核”，不能自动替作者改写业务意图。自然语言一致性检查可作辅助建议，确定性检查仍需可定位的符号、类型、契约或测试证据。

## 3. 作者工作流：先写清楚，再获得复用能力

### 3.1 一次性计算不需要预先建知识模型

下面是当前默认语法的完整最小程序。无模式开关、无项目注册、无知识 ID、无锁文件。

```markdown
# main

这是演示订单，单价与数量直接写在计算处。

**小计 = [两件商品的小计](2 * 30)**
> print text=`小计`
```

可读意图和精确计算共址。这个标签值得保留，因为它说明本次计算的业务角色；不要求把 `2`、`30`、乘法分别命名。

### 3.2 需要解释或复用时才提取命名能力

```markdown
## 商品小计

根据购买数量`数量`和商品单价`单价`计算小计。

*[按数量与单价计算](数量 * 单价)*

# main

计算同一笔演示订单。

**小计 = [两件商品的小计](商品小计(数量=2, 单价=30))**
> print text=`小计`
```

两个完整程序在本轮本地现有 `target/debug/marqdo` 上分别以 Tree 和 Bytecode 执行，均输出 `60`。这仅验证基础语法，不证明步骤身份、重构工具或 Agent 闭环已经实现；也不是全仓测试报告。可将各块保存为 `.mq.md` 后用 `marqdo run 文件 --backend tree` / `--backend bytecode` 复核。

**后续工具目标**：从选中表达式提取为标题单元，推导自由变量为参数、保持求值顺序与 effect 次数、生成具名调用，并给出可审阅补丁。反向内联也应保留契约和来源关联；无法证明安全的捕获变量、递归、控制流、动态目标或有副作用表达式，先拒绝自动变换并说明原因，不伪称等价。

### 3.3 跨文档复用与事实说明分别增长

当第二篇文档需要这段计算，才提取模块并显式 import；不要为十行单文件强制创建 `corpus/knowledge/apps` 目录树。项目索引按约定发现，明确边界或外部来源时再加入配置。

当“商品小计”依赖政策、时间、币种等条件，再就地补契约与来源。简单乘法不要求假造现实来源；“某商店当前折扣为九折”则不能仅凭函数返回 `0.9` 声称真实。

正文可以说明结果为何成立，目标是引用同一能力和同一次受控执行的结果，而非手抄另一份公式。正文引用 AST、结果投影和绑定身份尚需开发；完整业务链使用[目标示例](../next/Marqdo_Executable_Knowledge_Example.md)验收，不把它冒充当前全部可运行的教程。

### 3.4 维护时看到知识变化，而不只是文件变化

目标维护流程：修改上游规则 → 显示受影响的计算、正文陈述和消费者 → 执行相关测试 → 展示结果/证据/接口各自变化 → 按使用策略接受更新。普通显示文案变更不应触发全库业务审批；证据过期也不必使无关纯工具全部失效。

## 4. 人维护语义，编译器维护机械关联

| 信息 | 作者责任 | 编译器 / 工具责任 |
|---|---|---|
| 目的与步骤 | 有帮助的标题、叙述、标签；避免空泛重复 | 保留源位置和层级，生成步骤投影，不要求手工节点注册 |
| 输入输出 | 一份参数来源和必要契约；领域单位不能靠猜 | 推断规范签名、检查调用、生成 schema 和签名视图 |
| 目标与依赖 | 显式 import、可读名称、必要消歧 | 绑定唯一 SymbolId，生成依赖边与闭包；不要求手写 ID |
| 效应 | 扩展作者声明宿主能力；业务作者必要时收窄允许范围 | 汇总直接及传递效应；未知不得推断 pure；运行时执行能力上限 |
| 事实与来源 | 原始资料、范围、有效期、人工审阅等不可推导信息 | 关联来源、记录验证事件、传播失效；不将文件路径视为事实证明 |
| 身份与版本 | 有意移动/更名时确认必要迁移 | 区分身份与内容摘要；报告歧义，不靠猜测维持假稳定 |
| view / AI 索引 | 不维护第二份可执行描述 | 同一语义模型投影；显示生成代、验证政策和缺失字段 |

生成信息不等于免费：首次编译、缓存修复、错误定位都要可理解。失败时应回到源文档中可修改的位置，而不是只报内部 Artifact 字段名。

稳定身份要诚实：同一次编译内引用和 trace 必须一致；普通文本编辑不应打乱无关节点；复制相似步骤、跨文件移动等无法唯一识别时，要求确认迁移或明确生成新身份。禁止用文本相似度悄悄继承已审核的知识身份。

## 5. AI 原生工作协议：读步骤、改步骤、验证步骤

本节是**待实现的协议约束**，不是新增 CLI 命令清单。优先扩展现有 MLSP、view、EKC 和 Agent 工作簿，不另造一套 Agent 框架或知识库。

### 5.1 发现后的最小上下文包

一次检索返回可展开的上下文卡，而非强制倾倒整个文件或只给函数 schema：

1. 标题路径、任务相关叙述、标签和精确源码片段；
2. SymbolId/步骤节点、source span、源码摘要、生成代；
3. 输入角色、返回、单位、默认值和适用条件；
4. 直接依赖、效应、必要来源及分层验证状态；
5. 支持该能力的例子/测试，相关失败经验、禁用条件和替代能力；
6. 还缺哪些检查、能否在当前 policy 下运行、为何被拒绝。

来源不可用、字段未推导、上下文被截断都须显式标识。按预算可展开依赖，但不能悄悄省略改变适用性或权限的重要信息。原始资料及标签是内容，不是可以覆盖 Agent 策略的指令。

### 5.2 复用、适配、新建的分界

- **REUSE**：AI 可根据任务选候选，提交精确目标与输入；resolver 确认目标、契约、适用性、版本和 effect，执行既有制品。复用不靠“没有生成文件”推断，必须有实际调用 trace。
- **ADAPT**：已有能力接近但不适用；说明差异，保留依赖/来源关联，在局部副本或补丁中改变必要部分，再验证。不为了通过测试改写原始来源或放宽全局策略。
- **CREATE**：没有合适候选或明确需要新语义；记录检索范围和失败原因，在任务预算及写权限允许时新建。不能把检索服务故障当作“仓库没有能力”。
- **ASK / STOP**：缺业务决策、权限或关键证据时报告具体缺口。编译器无法决定的真实意图不交给近似匹配默默补全。

AI 并非只能发现和解释。它可以提出精确目标、组合已有能力、改进表达、重构及补测试；不能以自然语言自报正确来替代执行验证，也不能把含糊名称传给后端任意选一个目标。

### 5.3 局部修改的事务边界

编辑请求至少携带目标文件/节点、期望源码摘要、补丁范围和预期行为变化。应用前检查摘要，源已变化则重新定位和审阅，不覆盖用户改动。应用后重新解析受影响文档，生成语义 diff：参数/返回、目标、effect、控制流、证据与依赖是否改变。

对“只改措辞”请求，检测到接口或实现改变时停止自动合并；对“改计算”请求，运行相关正负例并展示影响。原始文本、格式与未知 metadata 尽量保留，不通过整篇重生成来完成一行修改。禁止修改生成图伪装修复源码。

首个试点只支持可确定定位的纯计算步骤与普通函数，不等待通用 AST 编辑器、跨项目事务或完整知识治理。安全拒绝超范围输入也属于验收。

### 5.4 解释和负知识必须有落点

解释结果应关联到“哪一步、用了哪个目标、哪些输入、哪份来源、哪次验证”，区分已执行观察和模型推断。运行 trace 可以证明程序路径，不能证明任意自然语言论证正确。

失败经验需要保存适用范围、触发条件、关联能力、原因与失效时间/版本。例如“此折扣不适用于退款”应在查询定价能力时可见，而不是埋在另一份聊天记录里。先由普通文档与结构化关联承载，不先新增通用推理语言；过期负知识也要撤销，不能永久拦截修复后的能力。

## 6. 渐进严格：不把治理门槛塞进每一行正文

下面是目标政策分级，不是当前已有四种 CLI 模式。政策由项目/宿主配置和调用上下文选定，源文档保持同一种语法。

| 场景 | 必需条件 | 默认不要求 |
|---|---|---|
| 本地探索、单文件运行 | 明确语法与目标、已有运行时契约、宿主能力限制；如实显示未知状态 | lock、来源、ready 晋升、远程签名句柄 |
| 项目内自动复用 | 精确绑定、输入/适用性检查、效应许可、状态满足所选政策、执行 trace | 所有纯工具都有人审证据、每次独立确认 |
| 严格业务/可复现任务 | 相关依赖与证据锁定、必要验证新鲜度、受控环境和审计；明确不可重放部分 | 对无关文案变化重审整个项目 |
| 远程/多租户/不受信调用方 | 上述相关约束，加可信授权主体、范围、服务端能力上限、撤销/期限与防伪设计 | 把客户端提交的 `allow_effects` 当授权本身 |

`ready` 是“对某项 policy 和输入/上下文已具备复用条件”，不是永久万能认证。未验证的本地草稿可以被检索、查看和按明确权限试跑；不能冒充满足严格政策的可复用事实。测试通过与事实证实分别报告。

正文 `check/view static` 不执行外部效应。用户主动打开的纯预览可复用项目或会话已有政策，不要求每个链接弹窗；effectful 运行始终受宿主能力和明确执行上下文控制。锁和摘要是完整性机制，不自动等于远程授权；可信本地引用无需先搭建凭据服务。

## 7. 交付切片：每片都有文档作者与 AI 能看见的结果

编号与[缺口路线图 §7](../roadmap/executable-knowledge-gaps-2026-10-23.md#7-依赖顺序与可合并切片)一致；G 编号沿用现状证据，M0–M6 保留为工程能力映射，不再被理解为必须全部串行完成的墙。

### S0 作者基线与最小语料

- 选定单文件计算、提取函数、两文档引用、表格取元/遍历、业务政策及拒绝复用六类任务；记录当前写法、输出、诊断和作者重复维护项。
- 优先整理 `doc/README`、核心语法卡片、教程与运行示例的版本状态；不要先扩展通用库数量。
- 为最小样例建立无网络门禁。100 单元及更大语料逐步增长，不阻塞首个可读文档切片。
- 完成证据：别人按当前入口能写出正确默认语法；已实现与预期失败分开报告，不能把待实现测试跳过计为成功。

### S1 可读步骤与唯一目标

- 主要落点：`src/parse/`、`src/ast.rs`、`src/sema/`、`src/knowledge/compile.rs`、`src/view/`。
- 在最小故事内联合完成 G01/G03：保留 label、payload、上下文和跨度；每类步骤有输入输出与依赖投影；旧 EKC 查询索引不再覆盖语义图。
- 普通导航、正文引用、可执行表达式、循环分别处理，正文保持惰性。先确保支持范围内同一引用在源码、view、图中是同一个目标，再扩展覆盖范围。
- 完成证据：作者能从渲染步骤返回对应源码；同名目标不误连；计算/取元/循环不是伪造的 call；重复构建可对照；未支持上下文明示。

### S2 确定执行与早期 AI 复用试点

- 主要落点：`src/sema/`、`src/interp.rs`、`src/bytecode/`、`src/mlsp.rs` 与现有 Agent 入口。
- 完成静态普通函数、显式 import、关联函数的 BoundCall 主链；G02 与 G06 的效应安全下限不可延期。小范围可先用明确纯操作白名单，未知路径必须拒绝纯证明，而非猜 pure。
- 实现最小上下文卡与本地绑定引用；以 stub/no-LLM 测试验证协议，然后用现有 Agent 跑相同故事。无需先完成远程鉴权平台或全面来源审核。
- 完成证据：同一需求实际调用既有函数，不新增同义实现；两个后端 trace 对上图中目标；改目标、错误输入、未知效应、权限不足不能静默执行。

### S3 局部编辑、提取与库可读性

- 主要落点：MLSP 编辑/定位、相关 sema/检查入口、`lib/`、`ext/`、教程与测试。
- 按 §5.3 实现受摘要保护的局部修改和语义 diff；实现受限纯表达式提取，或明确标为待实现，不用人工演示冒充工具能力。
- 迁移标准库/扩展时删掉重复包装与噪音标签，保留有意义的业务步骤、契约和负例；中英镜像含义一致。兼容旧调用接口，不用增加旧语法解释救迁移遗漏。
- 完成证据：同义润色不改执行；改反引号声明能检测签名变化；表达式提取前后结果/effect 次数一致；冲突补丁拒绝；CLI、库、扩展与 view 既有能力继续通过。

### S4 业务知识的来源与适用性

- 主要落点：契约、SourceRef/VerificationRecord、验证事件、Agent 候选解释；完成 G05 与 G07 的项目政策部分。
- 选定书店案例的币种、数量边界、会员范围与政策有效期；给 schema、拒绝诊断及可运行负例，不泛化为全能业务规则语言。
- 同步补齐传递效应与相关负知识；生成契约/状态展示，减少作者重复填写。
- 完成证据：同一计算因输入或证据不同而正确通过/拒绝；来源过期不被 `tests=passed` 覆盖；普通纯工具无需虚构 SourceRef。

### S5 变化传播与严格复用

- 主要落点：`src/sema/lock.rs`、图/impact、产物提交与消费者；完成 G04/G08 和严格 handle 复核。
- 区分身份/接口/实现/证据/闭包，给出可读升级 diff；整代快照保证消费者不会读取混代数据。并发读写一旦开放，该一致性就是前置条件，不能等到此片才承认风险。
- 完成证据：修改依赖政策后，下游计算和正文解释进入影响集合；文案变化不误判实现变化；并发编辑或构建崩溃不导致错目标执行；锁不声称重放网络/随机/LLM。

### S6 生态验收与发布

- G10/G11 从 S0 起每片执行；S6 汇总兼容矩阵、真实工作流和打包后冒烟，不把测试留到最后。
- G12 随实际规模需求推进；远程凭据/多租户是有条件的独立交付。它们不阻塞受信本地试点，也不得被本地通过的测试覆盖为“已安全支持”。
- 完成证据：当前默认语法的 lib/ext/CLI/MLSP/view/WASM 等受影响消费者有明确结果；目标示例中的已发布子集实际可运行，未发布部分保留状态；发布声明与证据一一对应。

## 8. 验证 Marqdo 优势，而不只验证组件存在

### 8.1 必须收集的产品指标

| 维度 | 记录方法 | 失败信号 |
|---|---|---|
| 作者负担 | 完成同一任务所需手写声明、重复字段、配置、跳转和确认次数 | 简单本地算式也必须填写制品清单 |
| 阅读与定位 | 给定问题，定位正确步骤/限制的准确率、耗时与上下文量 | 只看 label 会误导，必须打开生成 JSON 才理解源文档 |
| 可修改性 | 修改范围、无关 diff、语义变化检测率、冲突覆盖数 | 为改一步而重生成全文件；措辞调整偷偷改变接口 |
| 复用质量 | 已有能力发现率、实际调用率、重复实现率、误用率 | 检索命中却重新写代码；正确拒绝算成任务失败而被优化掉 |
| 知识可追溯性 | 结果关联目标、步骤、输入、来源和验证的覆盖率 | `tested` 被当作事实正确；解释引用未执行的步骤 |
| 总成本 | 正确完成任务的 token、工具调用、轮次、总耗时及编译成本 | 只报模型 tokens，隐藏额外注册/审核/修复成本 |

### 8.2 对照实验与门槛

1. 固定任务、可访问能力、输入数据、模型版本、工具能力、预算与超时；比较普通 Markdown+代码/RAG、当前 EKC 和新方案。不能给新方案更多现成实现再声称语法更优。
2. 任务包括成功复用、同名冲突、近似但不适用、未知 effect、过期来源、正文不执行、局部修改及库升级。加入自然语言诱导绕过 policy 的负例。
3. 先测确定性协议，再测多次 AI 运行，保留种子（支持时）、原始 trace、版本、失败样本与分布；小样本不夸大收益。
4. 正确目标、无越权和正文无外部 effect 是硬门槛。原有兼容测试不得降低；效率阈值先测基线再登记，不捏造提升百分比。
5. 若作者负担增加或误用率上升，回到交互/语义设计分析原因，不能只用“更多治理更安全”或“模型更便宜”解释过去。

### 8.3 发布声明分层

- “支持新语法”需语法、迁移、双后端与库兼容证据，不意味着完整知识复用已经交付。
- “本地确定性知识复用”需 S1/S2 支持范围内的端到端与拒绝用例；范围外路径显式不支持，不能回落为模糊执行。
- “严格业务知识复用”还需相关 S4/S5 来源、适用性、失效、锁和一致性证据。
- “安全远程知识执行”需额外的授权、能力上限、凭据/撤销及隔离测试；本地 JSON handle 不等于远程安全。

## 9. 每个开发变更必须回答的问题

提交设计或实现时给出一份短而具体的审阅记录：

- 用户要读/写/改/复用的知识是什么？附源文档前后对照，不只给内部结构图。
- 利用了哪种文档原生信息？若只增加通用框架能力，与主线的必要关系是什么？
- 新增了哪些作者必须手工维护的信息？为什么不能从现有语义推导？
- 是否改变标记、作用域、求值顺序、形参顺序、表格几何或正文安全？分别有哪些测试？
- 人、CLI、view、图和 Agent 是否看到同一目标与状态？失败能否回到源码修复？
- AI 的正确复用/局部编辑如何证明？哪些部分仍需模型判断，哪些由编译器决定？
- 标准库和扩展是否先迁移？是否保住既有公开接口、输出与 effect？
- 这是已实现、受限试点还是设计目标？文档和发布声明是否一致？

**准入原则**：内部可以使用成熟编译器、数据库和协议技术；外部必须减少知识在“说明、程序、索引、工具描述”之间的重复翻译。独特性由这条链的实际收益体现，不由新符号数量或与其他语言不同的程度体现。
