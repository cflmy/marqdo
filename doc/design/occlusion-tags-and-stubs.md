## 0. 四条定调

1. **`[]` 里是纯粹的描述文字，对执行没有任何作用。**
   编译器**不解析**它，只在里面**做关键词匹配**（供统计、清单、LLM 待办）。
2. **关键词不是语法。** `[某个功能，没开发完成]()` 合法；`[某某功能开发中]()` 也合法，
   **不需要任何分隔符**——匹配就是子串检索。
3. **空载荷必须提示。** `()` 为空 → **warning**；若描述里已有关键词（已申报），则不打扰。
4. **强力推荐 LLM 这么写**：写不了真接口就"申报"，别"假装"。
   这一条要写进 agent 的 standing 提示词，让 Marqdo 从"语言"变成"**工程习惯**"。

一句话：

> **描述给人读，关键词给机器数；两者都不执行；空着不写会被提醒。**

---

## 1. 为什么要允许「假接通」

模型被要求"接入搜索"时，最省力的是写个返回固定值的函数，然后声称已接通。

| 处理方式 | 结果 | 问题 |
|---------|------|------|
| **A 禁止**（提示词"不许伪造"） | 模型改用更隐蔽的伪造 | 不可检测、不可计数 |
| **B 放任** | 静默假功能 | 文档撒谎，且**没人知道欠了多少** |
| **C 申报**（本方案） | 假接通仍允许，但**写进描述** | 代码照跑；欠据可数、可查、可结算 |

C 的关键：**不改道德要求，改激励**——申报比伪造省力（多写几个字），且申报后代码照样跑。

## 2. `()` 内部语法定稿

### 2.1 取元

| 语义 | 写法 |
|------|------|
| Map 取成员 | `at(表, 键)` |
| List 第 n 项（1-based） | `at(列表, 1)` |
| 缺键取默认（不崩） | `get(表, 键, 默认值)` |

### 2.2 调用

| 形态 | 写法 |
|------|------|
| 位置实参 | `加一函数(31)`（逗号可选：`加一函数(31 2)`） |
| 具名实参 | `计税(档位=2, 金额=100)` |
| **带空格 callee** | `加一 号(31)` → callee = 第一个 `(` 之前的全部文本 |
| 库路径 / 方法 | `txt.str_trim(s)` / `obj.方法(x)` |

实测：`加一 号(31 )` → `32`；`> 加一 号 31` → `unknown function 加一`。
**`(` 是明确分隔符，空格不再参与切词**——这是缺陷 D8 的结构性解法。

### 2.3 循环

```markdown
- [从篮子里取出的每个果子](遍历 篮子 为 果)
```

### 2.4 空载荷 → **warning**

```markdown
[某某功能，还没做]()        # ⚠️ label.empty_payload
```

| 情形 | 级别 | 说明 |
|------|------|------|
| `()` 为空，描述**无**关键词 | **warning** | 「空载荷遮蔽：请补 `()`，或在描述里写明未完成状态」 |
| `()` 为空，描述**有**关键词（已申报） | 不报 | 已申报的桩，提示即噪音 |

**为什么要 warning**：空 `()` 意味着"这段遮蔽里没有可执行内容"。
它要么是忘了写实现，要么是桩——**两者都必须被人看见**。
有申报就不打扰，是为了守住"说过的不再重复"。

## 3. 描述文字与关键词

### 3.1 描述是自由文本

```markdown
[某个功能，没开发完成]()                     # ✅ 合法
[某某功能开发中]()                           # ✅ 合法，且会被统计（无分隔符）
[按 `税率` 与 `档位` 计算应缴税额](…)          # ✅ 反引号 = 可校验断言
```

唯一约束：**不能为空**（`[](…)` → `label.missing`）。
`[]` 不参与执行、类型、作用域。

### 3.2 关键词表（v1：核心词 + 同义词）

| 组 | 关键词（任一命中即算） | 计入 |
|----|----------------------|------|
| **未完成** | `待开发` `未开发` `开发中` `未实现` `待实现` `未接` `接口未接` `TODO` | 未完成 |
| **假数据** | `模拟` `假数据` `桩` `占位` `stub` `mock` | 未完成 |
| **演示** | `示例` `样例` `demo` | 示例类 |
| **不稳** | `实验` `试验` `experimental` | 实验类 |
| **将删** | `废弃` `弃用` `deprecated` | 清理项 |
| **待核** | `待校验` `未验证` `待确认` | 待核类 |

**闭合但可扩**：这张表是**检索词表**，不是语法关键字。
扩充词表**不影响任何语法规则**（后续可支持 frontmatter 自定义，见 §9）。

### 3.3 识别规则：**纯子串匹配，无任何位置/分隔符要求**

```rust
// 语义示意：对描述原文做子串检索
for (group, words) in KEYWORDS {
    if words.iter().any(|w| label_text.contains(w)) { tags.insert(group) }
}
```

| 写法 | 识别 |
|------|------|
| `[某某功能开发中]` | ✅ 无分隔符 |
| `[搜索接入，待开发]` | ✅ 逗号 |
| `[搜索接入-待开发]` | ✅ 连字符 |
| `[【待开发】搜索接入]` | ✅ 括号 |
| `[这段还没写完]` | ❌ 无关键词（合法但**不计数**） |
| `[功能，待开发中]` | ✅ 命中 `待开发`（子串） |

- 最多取 **3 组**；多组时以最强者决定语义：`未完成 > 假数据 > 示例 > 实验`；`将删` 正交
- **识别不到不报错、不提示**——描述自由，机器只是"看见了就记一笔"

### 3.4 误判怎么处理（诚实说明）

子串匹配必然有误判：

```markdown
[这段不属于待开发范围，已全部完成](真实现())     # 会命中「待开发」
```

**处理原则：不设语法级否定词，靠"看得见"解决。**

- 误判只会让**债务数字偏大**，不会让程序出错（关键词不参与执行）
- `stubs --list` 会**列出描述原文**，人一眼能看出是误判
- 若确需排除，写反面词即可：把"待开发"改成"已完成"，或加一句"（非待开发）"？——
  注意后者仍会命中。**v1 不做否定语法**；若实际使用中误判过多，再做
  「否定词窗口」（如 `不再|无需|非` + 关键词 → 不计），作为 v1.1 的可选项

## 4. 桩的语义

### 4.1 三条规则

| # | 规则 | 原因 |
|---|------|------|
| 1 | **桩必须能跑**（不得报错） | 否则整篇文档被阻断 |
| 2 | **桩必须可见** | 有关键词（申报）或空载荷（触发 warning） |
| 3 | **桩不得被当成已完成** | 编译器/LLM 读取时能看到 pending 状态 |

### 4.2 桩返回什么

| 手段 | 写法 |
|------|------|
| 空载荷 | `[某某功能开发中]()` → `None` |
| 常量占位 | `[税率预报，模拟](0.1)` |
| 假数据 | `[搜索结果，模拟](json.parse text="[]")` |
| **桩 + 契约（推荐）** | 配合返回契约声明类型 → 桩是"有类型的洞" |

```markdown
## 搜索

| 返回 | 类型 | 说明 |
|------|------|------|
|  | list | 命中列表（当前未接） |

[按关键词检索，接口未接，模拟](json.parse text="[]")
```

### 4.3 惯例（不强制）：桩返回值带 `stub: true`

```markdown
[ERP 推送，模拟](json.parse text={"ok":true,"stub":true})
```

## 5. 工程化：把"申报"变成习惯

这是本设计真正的落点——**它不只是一个语法特性，而是一套工程习惯**。

### 5.1 写进 agent 提示词（强烈推荐）

```text
当你要接入一个你无法真正接入的能力时：
1) 不要静默伪造，也不要声称已完成。
2) 用遮蔽语法写出该能力，并在描述里写明状态，例如：
     [按关键词检索，接口未接，待开发]()
     [搜索结果，模拟](json.parse text="[]")
3) 桩必须能跑（不得报错），返回值建议带 stub: true。
4) 收尾时用 stubs 工具确认剩余未完成项。
```

**为什么这条对 LLM 特别有效**：它把"编造"变成"填表"——
模型不需要判断"这算不算伪造"，只需要写出状态词。

### 5.2 三个 LLM 可用的工具面

| 工具 | 用途 |
|------|------|
| `stubs --json` | 待办清单（位置 + 描述 + 关键词） |
| `stubs --changed` | 本次变更中被改过的桩 → 判断是否已完成 |
| `labels --grep 词` | 在描述里搜任意关键词（不限词表） |

### 5.3 工程指标（可进 CI 报告）

| 指标 | 含义 |
|------|------|
| `pending_count` | 未完成桩数（棘轮：只拦新增） |
| `unlabeled_empty` | 空载荷但无关键词（**warning 数**） |
| `stub_ratio` | 桩数 / 遮蔽总数（衡量"文档里有多少是承诺而非实现"） |
| `stub_age` | 桩存在时长（需 VCS，可选） |

### 5.4 检索语法示例

```bash
marqdo stubs                      # 人类读：按文件列出未完成项
marqdo stubs --json               # LLM 读
marqdo stubs --check              # 棘轮：数量增加则非零退出
marqdo stubs --changed            # 本次变更中被改过的桩
marqdo labels --grep 接口未接      # 任意词检索描述
```

## 6. 生命周期：欠据会自己结清

```
① 写桩    [按关键词检索，接口未接，待开发]()
                ↓
② 计数    marqdo stubs → 待开发 +1
                ↓
③ 开发    换成真实 HTTP 调用
                ↓
④ 复核    复核时去掉关键词、改写描述
                ↓
⑤ 债务-1  stubs 数字自动下降
```

### 6.1 带桩关键词的遮蔽豁免 stale

| 情况 | stale 行为 |
|------|-----------|
| 含 `未完成` / `假数据` / `将删` 组词 | **豁免** |
| 含 `示例` / `实验` | 正常报 |
| 空载荷 | **豁免**（它就是桩） |
| 无关键词、有实现 | 正常报 |

理由：桩本就是"未完成"，描述已明说。若桩一被改动就报 stale，
12 个桩会变 12 条常驻警告——**正好制造我们要消灭的疲劳**。

### 6.2 防"做完了忘去掉关键词"

- `stubs --changed`：列出本次变更中被改过的桩
- 会话末汇总带一行 `stubs_touched: 2`（只给数字，不逐条）

---

## 7. 与防疲劳机制的协同

| 机制 | 作用 |
|------|------|
| 桩豁免 stale | 12 个桩不会变成 12 条常驻警告 |
| 债务用**棘轮**（基线 + 只拦新增） | 老债不阻塞、新债立刻拦 |
| `stubs` 是按需命令，不进 `check` 人类输出 | 零噪音 |
| 关键词识别不到**不报错** | 自由措辞不会被机器纠正 |
| **空载荷只在"未申报"时警告** | 说过的不再重复 |

## 8. 编译器实现点

| 位置 | 要做的事 |
|------|---------|
| `src/parse` | 解析 `[描述](实现)`，**原样保存描述字符串**（不解析关键词） |
| `src/ast.rs` | `Expr::Occluded { label: String, tags: Vec<TagGroup>, inner }` |
| `src/label.rs`（新增） | **检索器**：`label_text.contains(word)` 子串匹配；`TagGroup` 闭集枚举；L1 引用一致性；T1 前后对比 |
| `src/check.rs` | 三条：`label.missing`（error）、`label.ref_dangling`（error）、**`label.empty_payload`（warning，有关键词则不报）** |
| `src/interp.rs` | **关键词不影响求值**；空载荷 → `None` |
| `src/main.rs` | `marqdo stubs [--json/--check/--changed]`、`marqdo labels --grep` |
| `src/mlsp.rs` | `stubs` 方法；会话汇总带 `stubs_touched` |
| `src/view/render.rs` | 桩徽章（显著而非隐藏） |
| `doc/` | 教程补"描述与关键词 + 申报习惯"；陷阱手册补一节 |

**关键**：关键词走"**检索层**"，与语法解析解耦——词表可随时扩充，不动语法。

## 10. 风险与取舍

| 风险 | 说明 | 缓解 |
|------|------|------|
| 子串误判 | `[不属于待开发范围]` 会命中 | 只影响计数不影响执行；`stubs --list` 显示原文可人工识别；必要时 v1.1 加否定词窗口 |
| 债务指标被稀释 | 什么都标 | `--changed` / `--list` 展示构成；按用户判断接受代价 |
| 桩腐化 | 做完了忘去掉词 | 改动时提示（§6.2），不靠常驻警告 |
| 假功能上生产 | 最坏情况 | `view` 显著标记；知识库仓可 `--check` 为 error |
| 词表不够用 | 想标别的 | 检索层可扩（后续 frontmatter 自定义），不动语法 |
| LLM 滥用关键词逃避检查 | 把真实现标成待开发 | 关键词**只增加可见性**，不减少任何检查；豁免 stale 的代价是计入债务 |
