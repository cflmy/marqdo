# 遮蔽描述与内置标签：让「假接通」变成可见的欠据

| | |
|---|---|
| 状态 | **Proposed · 待批准**（含描述自由性、标签检索规则、桩语义、内部语法定稿） |
| 日期 | 2026-10-22 |
| 提出 | 用户：允许 LLM 的"假接通"，但描述里写清；编译器在描述内**检索**，让 LLM 知道还有多少没开发 |
| 修正 | **`[]` 内部是自由描述文本，标签只是「可被检索的内置词」——不是语法** |
| 前置 | [occlusion-syntax.md](occlusion-syntax.md) |

---

## 0. 三条定调（本文全部结论都由此推出）

1. **`[]` 里是纯粹的描述文字，对执行没有任何作用。**
   编译器**不解析**它，只在里面**检索**（给统计、清单、LLM 待办用）。
2. **标签是内置词，不是语法。** 写成 `[某个功能，没开发完成]()` 完全合法；
   想让它**被统计**，再顺手写上内置词 `[某个功能，没开发完成。待开发]()`。
3. **标签的作用是"让人和模型多看一眼"**，不是审批、不是门禁。
   所以**标在任何地方都无害**——哪怕标在已知常量上，它只换来一次复核。

一句话：

> **描述给人读，内置词给机器数；两者都不执行。**

---

## 1. 为什么要允许「假接通」

模型被要求"接入搜索"时，最省力的是写个返回固定值的函数然后声称接通。

| 处理方式 | 结果 | 问题 |
|---------|------|------|
| **A 禁止**（提示词里"不许伪造"） | 模型改用更隐蔽的伪造 | 不可检测、不可计数 |
| **B 放任** | 静默假功能 | 文档撒谎，且**没人知道欠了多少** |
| **C 申报**（本方案） | 假接通仍允许，但**写进描述** | 代码照跑；欠据可数、可查、可结算 |

C 的关键：**不改道德要求，改激励**——申报比伪造省力（多写几个字），且申报后代码照样跑。

与遮蔽语法的核心定理同源：

> 遮蔽创造信任负债。**桩是明写出来的负债；不写出来的桩，是看不见的诈骗。**

## 2. 内部实际语法定稿（用户授权）

`()` 内统一为**函数形**，不再有"取元/调用/循环"三套写法。

### 2.1 取元

| 语义 | 写法 |
|------|------|
| Map 取成员 | `at(表, 键)` |
| List 第 n 项（1-based） | `at(列表, 1)` |
| 缺键取默认（不崩） | `get(表, 键, 默认值)` |

### 2.2 调用

| 形态 | 写法 |
|------|------|
| 位置实参 | `加一函数(31)`（逗号可选：`加一函数(31 2)`） |
| 具名实参 | `计税(档位=2, 金额=100)` |
| **带空格 callee** | `加一 号(31)` → callee = 第一个 `(` 之前的全部文本 |
| 库路径 / 方法 | `txt.str_trim(s)` / `obj.方法(x)` |

**实测**：`加一 号(31 )` → `32`；而 `> 加一 号 31` → `unknown function 加一`。
`(` 是明确分隔符，空格不再参与切词——**这是缺陷 D8 的结构性解法**。

### 2.3 循环

```markdown
- [从篮子里取出的每个果子](遍历 篮子 为 果)
```

### 2.4 空载荷

```markdown
[某某功能，还没做]()
```

- 描述非空时，`()` 可以为空 → 返回 `None`，文档照样能跑
- **空载荷 = 桩的默认形态**，会被自动计入 `stubs --uncounted`（见 §5.3）

## 3. 描述文字与内置标签

### 3.1 描述是自由文本

```markdown
[某个功能，没开发完成]()                      # ✅ 合法，纯人话
[某个功能，没开发完成。待开发]()               # ✅ 合法，且会被统计
[按 `税率` 与 `档位` 计算应缴税额](…)          # ✅ 可校验引用（反引号 = 断言）
```

**规则**：`[]` 内容**不参与执行、不参与类型、不参与作用域**。
唯一约束：**不能为空**（`[](…)` → `label.missing`，因为你没写描述）。

### 3.2 内置标签 = 可被检索的词（v1 词表）

| 标签 | 含义 | 计入 |
|------|------|------|
| **待开发** | 尚未实现 | 未完成 |
| **模拟** | 假接通 / 假数据 | 未完成 |
| **示例** | 演示质量，非生产 | 示例类 |
| **实验** | 可能随时变动 | 实验类 |
| **废弃** | 将被移除 | 清理项 |

词表是**闭集**——只有可枚举才能统计、门禁。自由措辞（"没开发完成"）不计数，
但**照样合法可读**。

### 3.3 识别规则（检索，不是解析）

| 位置 | 例子 | 是否识别 |
|------|------|---------|
| **描述结尾** | `[搜索接入，待开发]` / `[搜索接入-待开发]` | ✅ |
| **显式括号内**（任意位置） | `[【待开发】搜索接入]` / `[搜索接入【模拟】]` | ✅ |
| 句中裸词 | `[这个功能不需要待开发处理]` | ❌ 不识别（避免误判） |
| 拼错 | `[功能，待开发中]` | ❌ 不识别、**也不报错** |

- 最多识别 **3 个**；多个标签以**最强者**决定语义：`待开发 > 模拟 > 示例 > 实验`；`废弃` 正交
- 分隔符随意：`-` / `－` / `，` / `,` / 空格 / 无（`[功能待开发]` 也算结尾识别）
- **识别不到不报错、不提示**——描述是自由的，机器只是"看见了就记一笔"

### 3.4 为什么不许它影响执行

| 铁律 | 说明 |
|------|------|
| `[]` 永不执行 | 标签因此**不可能改变程序行为**；写错标签不会让程序崩 |
| 只影响诊断/统计/呈现 | 想让程序变，只能改 `()` |

## 4. 桩的语义

### 4.1 三条规则

| # | 规则 | 原因 |
|---|------|------|
| 1 | **桩必须能跑**（不得报错） | 否则整篇文档被阻断 |
| 2 | **桩必须可见** | 有内置标签 **或** 空载荷（自动计入"未标注"） |
| 3 | **桩不得被当成已完成** | 编译器/LLM 读取时能看到 pending 状态 |

### 4.2 桩返回什么

| 手段 | 写法 |
|------|------|
| 空载荷 | `[某某功能，没做]()` → `None` |
| 常量占位 | `[税率预报，模拟](0.1)` |
| 假数据 | `[搜索结果，模拟](json.parse text="[]")` |
| **桩 + 契约（推荐）** | 配合返回契约声明类型 → 桩是"有类型的洞" |

```markdown
## 搜索

| 返回 | 类型 | 说明 |
|------|------|------|
|  | list | 命中列表（当前为桩） |

[搜索接入，模拟，待开发](json.parse text="[]")
```

### 4.3 惯例（不强制）：桩返回值带 `stub: true`

```markdown
[ERP 推送，模拟](json.parse text={"ok":true,"stub":true})
```

下游即使跑通也能看出"这是假的"。建议写进教程，但不做检查。

## 5. 标签到底带来什么

### 5.1 四个收益

| 收益 | 说明 |
|------|------|
| **可统计** | `marqdo stubs` → 待开发 12 处、模拟 3 处 |
| **可门禁** | 棘轮：只拦"新增桩"，不追旧账 |
| **可给 LLM 当待办** | `stubs --json` → 模型直接知道还有哪些没做 |
| **促使人/模型复核** | **这才是最实在的**：看到标签就会去读那段实现 |

### 5.2 关于"标在已知常量上也无害"

你说得对，我上一版把它写成反例是错的：

```markdown
[税率](0.1)              # 描述
[税率，待开发](0.1)       # 多四个字 → 模型会来复核这个 0.1 是否正确
```

**代价**：债务指标被稀释（一个常量被算进"未完成"）。
**收益**：换来一次深入检查与阅读。

**我同意按收益优先**。但要留一个提醒机制（不报警）：
`stubs --changed` 与 `stubs --uncounted` 让人能看到债务构成，
避免"全是常量占位"把数字撑大而失去参考价值。

### 5.3 未标注的桩也会被看见

```markdown
[某某功能，还没做]()      # 没写内置词
```

它不会被 `stubs` 的"待开发"计数捕获，但会出现在 `stubs --uncounted`：

```
未标注的空载荷遮蔽 3 处（建议补一个内置标签，便于统计）
```

**只列清单，不报警。** 这样"允许自由措辞"与"债务可见"两者都保住。

## 6. 生命周期：欠据会自己结清

```
① 写桩    [搜索接入，模拟，待开发](json.parse text="[]")
                ↓
② 计数    marqdo stubs → 待开发 +1
                ↓
③ 开发    换成真实 HTTP 调用
                ↓
④ 复核    复核时去掉 -待开发、改写描述
                ↓
⑤ 债务-1  stubs 数字自动下降
```

**桩与新鲜度机制共用同一条复核回路。**

### 6.1 带桩标签的遮蔽豁免 stale

| 情况 | stale 行为 |
|------|-----------|
| 有 `待开发` / `模拟` / `废弃` | **豁免**（不报） |
| 有 `示例` / `实验` | 正常报 |
| 无标签、空载荷 | **豁免**（它就是桩） |
| 无标签、有实现 | 正常报 |

理由：桩本来就是"未完成"，描述已明说。若桩一被改动就报 stale，
12 个桩会变成 12 条常驻警告——**正好制造我们要消灭的疲劳**。

### 6.2 但要防"做完了忘去掉标签"

豁免的代价是债务可能永远挂着。对策（一次性、不催）：

- `marqdo stubs --changed`：列出**本次变更中被改过的桩** → 「这些桩实现已变，确认是否已完成」
- 会话末汇总带一行 `stubs_touched: 2`（只给数字，不逐条）

---

## 7. 与防疲劳机制的协同

| 机制 | 作用 |
|------|------|
| 桩豁免 stale | 12 个桩不会变成 12 条常驻警告 |
| 债务用**棘轮**（基线 + 只拦新增） | 老债不阻塞、新债立刻拦 |
| `stubs` 是按需命令，不进 `check` 人类输出 | 零噪音 |
| 识别不到标签**不报错** | 自由措辞不会被机器纠正 |
| 会话末汇总带 `stubs_touched` | 闭合，不重复 |

```json
// .marqdo/stubs.json（可丢弃缓存）
{ "待开发": 12, "模拟": 3, "示例": 5, "废弃": 1, "未标注": 3 }
```

## 8. 编译器实现点

| 位置 | 要做的事 |
|------|---------|
| `src/parse` | 解析 `[描述](实现)`，**原样保存描述字符串**（不解析标签） |
| `src/ast.rs` | `Expr::Occluded { label: String, tags: Vec<Tag>, inner }`；`tags` 由检索层填充 |
| `src/label.rs`（新增） | **检索器**：结尾识别 + `【】` 显式识别；`Tag` 闭集枚举；L1 引用一致性；T1 前后对比 |
| `src/check.rs` | 仅两条硬规则：`label.missing`（描述为空）、`label.ref_dangling`（引用悬空，error） |
| `src/interp.rs` | **标签不影响求值**；空载荷 → `None` |
| `src/main.rs` | `marqdo stubs [--json] [--check] [--changed] [--uncounted]`、`marqdo labels --grep 词` |
| `src/mlsp.rs` | `stubs` 方法；会话汇总带 `stubs_touched` |
| `src/view/render.rs` | 桩徽章（显著而非隐藏） |
| `doc/` | 教程补"描述与内置标签"；陷阱手册补一节 |

**关键设计**：标签走"**检索层**"，与语法解析解耦。
好处：词表可以随时扩充（甚至项目自定义），**不影响任何语法规则**。

## 9. 示例集（按 LLM 真实生成风格）

### 9.1 假装接入了搜索（空载荷）

```markdown
## 检索资料

| 参数 | 类型 | 说明 |
|------|------|------|
| 关键词 | text | 检索词 |

[按关键词检索，接口还没接]()
```

文档整体可跑；`stubs --uncounted` 会列出它。

### 9.2 同样的桩，写成可统计的

```markdown
[按关键词检索，接口还没接。模拟，待开发](json.parse text="[]")
```

`stubs` → 模拟 +1、待开发 +1；LLM 的待办清单里有它。

### 9.3 假算指标

```markdown
本季度 **[客户留存率，待开发](0.0)**，环比变化 **[留存环比，模拟](0.0)**。
```

叙述读得通顺，数字是 0（**不是编造的 0.73**），人和模型都看得见未实现。

### 9.4 假接通外部系统

```markdown
[ERP 推送，模拟](json.parse text={"ok":true,"stub":true})
```

### 9.5 已废弃

```markdown
[旧版鉴权，废弃](检查旧令牌())
```

### 9.6 任意措辞都行（不计数，但可读）

```markdown
[这段还没写完](0)
[等接口给到再做](json.parse text="{}")
```

## 10. 风险与取舍

| 风险 | 说明 | 缓解 |
|------|------|------|
| 债务指标被稀释 | 什么都标待开发 → 数字虚高 | `stubs --changed` / `--uncounted` 展示构成；**按你的判断接受这点代价** |
| 桩腐化 | 做完了忘去掉标签 | 改动时提示（§6.2），不靠常驻警告 |
| 假功能上生产 | 最坏情况 | `view` 显著标记；知识库仓可 `--check` 为 error |
| 自由措辞无法统计 | "没开发完成"不计数 | 正是取舍：**机器只数它认得的词**；需要统计就补一个内置词 |
| LLM 滥用标签逃避检查 | 把真实现标成待开发 | 标签**只增加可见性**，不减少任何检查（豁免 stale 的代价是计入债务） |
| 词表不够用 | 想标别的 | 检索层可扩（后续支持 frontmatter 自定义词表），**不影响语法** |
